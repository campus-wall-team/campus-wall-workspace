# 各仓库 AI 辅助开发策略

本文档介绍如何在校园墙各仓库中高效使用 Claude Code 辅助开发，包括常见任务模板和提示词技巧。

## 通用策略

### 开始工作前

进入仓库目录后，Claude Code 会自动读取 `.claude/CLAUDE.md`。你可以先确认它已理解项目：

```
请简要描述这个项目的架构和你在 CLAUDE.md 中看到的开发规范。
```

### 任务描述模板

```
【任务类型】新增功能 / 修复 Bug / 重构 / 文档
【涉及模块】xxx
【具体需求】...
【验收标准】...
```

示例：
```
【任务类型】新增功能
【涉及模块】community（帖子模块）
【具体需求】为帖子添加"置顶"功能，管理员可以将重要帖子置顶显示
【验收标准】
1. 帖子表添加 is_top 字段
2. 管理员可以调用 API 置顶/取消置顶
3. 置顶帖子在列表中优先展示
4. 最多同时置顶 3 条帖子
```

### 常用提示词模板

**新增模块**：
```
请在 community 模块下新增一个 "tag"（标签）子模块，包含：
1. Tag 实体类（id, name, post_count, create_time）
2. TagMapper 接口
3. TagService 接口和实现
4. TagController（REST API：列表、详情、创建、删除）
5. 遵循项目的命名规范和分层架构
```

**添加接口**：
```
请在 PostController 中添加一个 "搜索帖子" 接口：
- GET /api/v1/posts/search
- 参数：keyword（必填）、page、size
- 逻辑：根据标题和内容模糊搜索
- 返回：分页帖子列表
- 需要添加 Redis 缓存，缓存 5 分钟
```

**编写测试**：
```
请为 PostService 的 publish 方法编写单元测试，覆盖以下场景：
1. 正常发布
2. 标题为空（应抛异常）
3. 内容包含敏感词（应返回审核状态）
```

**添加 Flyway 迁移**：
```
请新增一个 Flyway 迁移脚本（版本号接续当前最高的 V4.4，如 V4.5__add_post_tag.sql）：
1. 创建 post_tag 关联表（post_id, tag_id）
2. 添加索引
3. 符合项目数据库规范；注意 MySQL 8 不支持 ADD COLUMN/CREATE INDEX IF NOT EXISTS，
   加列/加索引需用 information_schema + PREPARE 守卫保证幂等
```

### 注意事项

- AI 生成的 SQL 需要人工检查索引设计
- 涉及事务的操作需确认 `@Transactional` 注解
- 缓存逻辑需确认缓存 key 的唯一性和过期策略
- 不要依赖 AI 生成安全敏感代码（如加密、鉴权）

## campus-wall-graphrag（AI 服务）

### 适合 AI 辅助的场景

| 场景 | 效率提升 |
|------|----------|
| 添加新 API 端点 | 高 |
| Prompt 工程 | 中 |
| 图查询优化 | 低（需 Neo4j 专业知识）|

> 现状：graphrag 共 **9 个 HTTP 端点**（`/health`、`/index`、`/query`、`/query/stream`、`/ingest-post`、`/match-posts`、`DELETE /posts/{post_id}`、`/documents`、`DELETE /documents/{doc_id}`）。Neo4j 中除知识库的 `Document/Chunk/Entity` 建模外，已新增帖子侧 `Post`/`Item`/`Intent`/`Category`/`Tag` 节点建模，并有两个向量索引 `campus_chunk_vector`(Chunk) 与 `campus_post_vector`(Item)。提示词请围绕这些真实端点与模型给。

### 常用提示词模板

**新增端点（帖子入库 `/ingest-post`）**：
```
请在 main.py 中完善 POST /ingest-post 端点：
1. 入参 {post_id, intent, category?, text, images, tags}
2. 对有图帖调用 describe_image(VLM, qwen2.5vl) 读图，把图片特征描述拼进 text
3. 入库前经 sanitize.py 抹除手机号/微信号/学号等 PII
4. 写入 Neo4j 的 Post/Item 节点并向 campus_post_vector 写入 bge-m3 向量
5. 返回 {post_id, item_id, description, indexed}
```

**新增端点（自然语言召回 `/match-posts`）**：
```
请优化 POST /match-posts 的匹配逻辑：
1. 先做意图识别（lost_found|second_hand|part_time|team_up|daily）
2. 按意图过滤 + campus_post_vector 向量检索 topK
3. 每条返回 {post_id, score, intent, category, description, reason}
4. reason 用本地优先 chat 模型生成"为什么匹配"的简短理由
```

**VLM 读图（`describe_image`）提示词优化**：
```
请帮我优化 describe_image 的视觉提示词，使其对帖子配图输出更结构化的特征：

要求：
1. 聚焦可检索特征：物品类别、颜色、品牌、型号/书名版本、显著外观
2. 不臆测画面外信息，信息不足就只描述能看见的
3. 输出简洁中文，便于后续向量化与匹配
4. 不输出任何联系方式/人脸等隐私信息（PII 由 sanitize.py 兜底）
```

### 注意事项

- 涉及 LLM 的调用注意成本和延迟；graphrag 默认**本地 Ollama 优先 + 云端降级**（`_with_fallback`），改链路时分清本地 demo 与容器部署两条配置
- 图数据库查询需关注性能；新增节点/关系注意与 `campus_post_vector` 索引一致
- 不要暴露 Neo4j 查询细节到 API

### 1. 角色设定

```

```

### 2. 提供示例

```
请按照以下示例的格式，帮我生成代码：

示例：
```java
@GetMapping("/list")
public Result<PageResult<PostVO>> list(
    @RequestParam(defaultValue = "1") int page,
    @RequestParam(defaultValue = "10") int size
) {
    return Result.success(postService.list(page, size));
}
```

现在请为 CommentController 生成类似的列表接口...
```

### 3. 指定约束

```
请帮我实现，但注意以下约束：
1. 不能使用任何外部库
2. 时间复杂度不超过 O(n)
3. 内存占用不超过 1MB
```

### 4. 迭代优化

```
第一轮：请生成基础版本
第二轮：请添加异常处理
第三轮：请添加单元测试
第四轮：请优化性能

## 总结

AI 辅助开发能大幅提升效率，但需要注意：

1. **AI 是助手，不是替代**：关键业务逻辑仍需人工审查
2. **安全敏感代码人工审核**：认证、加密、支付等
3. **测试不可少**：AI 生成的代码必须经过测试验证
4. **持续学习**：根据项目特点积累自己的提示词模板
