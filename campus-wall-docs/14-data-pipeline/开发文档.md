# campus-wall-data-pipeline 开发文档

## 项目简介

campus-wall-data-pipeline 是校园墙项目的数据处理管道，负责从 campus_wall 的 MySQL 数据库中提取帖子和评论数据，经过清洗、脱敏处理后，推送到 campus-wall-ai 服务（原 campus-wall-graphrag 已并入 campus-wall-ai，端口 8011）构建知识图谱，为 AI 学长问答提供知识支撑。

> **注意：这不是爬虫。** 数据来源仅有两类合规渠道：① 本地 campus_wall MySQL 库（自有业务数据）；② 本机用 WeChatMsg 工具导出的微信聊天记录文件。整条链路是「本机导出 + 本地库抽取」的合规 ETL，不抓取任何外部站点。

**设计原则**：
- **隐私优先**：默认 dry-run，人工审查后再推送（必须显式 `--push` 才入库）
- **数据脱敏**：自动移除 PII 信息（手机号、身份证、姓名等）
- **可审计**：每个处理步骤都可追溯

## 核心模块说明

### 1. 数据模型 (schema.py)

```python
@dataclass
class KnowledgeUnit:
    """知识单元 - 统一的中间表示"""
    title: str                       # 主题/问题，作为 campus-wall-ai 文档标题
    content: str                     # 正文：脱敏后的「问题 + 参考答案/讨论结论」
    source: str                      # 溯源标识，如 "campus_wall:post:123"，只到来源类别
    tags: list[str] = field(...)     # 话题标签（来自 post.ai_tags），便于实体关联/过滤
    created_at: Optional[str] = None # 原始创建时间(ISO8601)，仅用于排序/增量，不入正文
```

关键方法：

| 方法 | 作用 |
|------|------|
| `stable_id()` | 基于 `source` 取 SHA1 前 16 位（`ku_` 前缀），保证重复灌入时幂等覆盖 |
| `is_valid()` | 校验 title/content 非空，过滤空单元 |
| `to_index_doc()` | 转成 campus-wall-ai `/index` 的 `{id, title, content, source}` 结构（tags 拼进 content 末尾） |
| `to_jsonl()` | dry-run 落盘，序列化为单行 JSON（含 id/title/content/source/tags/created_at） |

> 设计上存的是「问题—参考答案」这类**去身份**知识，而不是「谁在何时说了什么」。身份信息在 desensitize 阶段已被假名化/抹除。

### 2. 数据源适配器 (sources/)

#### campus_wall.py

从 campus_wall MySQL 提取数据，采用**两条独立查询**（先取帖子，再逐帖取评论），而非一次性 JOIN：

```python
# ① 查询正常帖子（注意 status=1 表示正常，is_deleted=0 表示未删）
#    post 表没有 title 列，标题由 content 前 40 字截取
SELECT id, user_id, content, ai_tags, location, is_anonymous, create_time
FROM post
WHERE status=1 AND is_deleted=0
ORDER BY id

# ② 对每个帖子单独查其评论，按点赞数倒序，每帖最多取 15 条
SELECT user_id, content, like_count, parent_id, create_time
FROM comment
WHERE post_id=%s AND is_deleted=0
ORDER BY like_count DESC, id ASC
```

提取逻辑：
1. 查询正常帖子（`status=1 AND is_deleted=0`）
2. post 表**无 title 列**，标题取帖子正文 `content` 前 40 字
3. 逐帖查其评论，按 `like_count DESC` 排序，**每帖最多保留 15 条**高互动评论作为「同学讨论」
4. 帖子作者与评论者经 `SpeakerPseudonymizer` 假名化（楼主 / 同学A / 同学B…），匿名帖不暴露 user_id
5. 无有效评论的孤帖跳过，其余组织为 `KnowledgeUnit`，`source` 形如 `campus_wall:post:{id}`，`tags` 来自 `ai_tags`

### 3. 数据清洗 (clean.py)

清洗规则：

| 规则 | 说明 | 示例 |
|------|------|------|
| 规范化 | 统一空格、换行、标点 | 去除多余空格 |
| 噪声过滤 | 去除无意义内容 | "顶"、"沙发"、"UP" |
| 广告过滤 | 识别并过滤广告 | 含联系方式的推广 |
| 问候语过滤 | 去除开场问候 | "大家好"、"请问" |
| 问答检测 | 识别有效问答对 | 确保有问有答 |

### 4. 数据脱敏 (desensitize.py)

脱敏规则（正则匹配 + 中文方括号占位符替换，顺序敏感：先匹配长/特异模式）：

| 类型 | 正则模式（要点） | 替换占位符 |
|------|----------|----------|
| 身份证号 | `\d{17}[\dXx]`（18 位，末位可 X） | `[身份证]` |
| 银行卡号 | `\d{16,19}` 连续数字 | `[银行卡]` |
| 邮箱 | `[A-Za-z0-9._%+\-]+@[A-Za-z0-9.\-]+\.[A-Za-z]{2,}` | `[邮箱]` |
| 手机号 | `1[3-9]\d{9}`（中国大陆） | `[电话]` |
| QQ 号 | **需前缀** `QQ/qq/扣扣/企鹅` + 5~12 位 | `[QQ]` |
| 微信号 | **需前缀** `微信/加微信/vx/wx/v信` + 字母开头账号 | `[微信号]` |
| 学号 | **需前缀** `学号/学籍号/考生号` + 8~14 位（无前缀长数字串不动，避免误伤年份/金额） | `[学号]` |
| 宿舍门牌 | `X栋/X座/X幢/X号` + 房间号（如 `3栋412室`） | `[宿舍]` |
| 链接 | `https?://...` | `[链接]` |
| 真实姓名 | NAME_BLACKLIST 花名册精确匹配（长名优先） | `[姓名]` |

> QQ / 微信 / 学号必须带语义前缀或门牌格式才触发，正是为了避免把普通长数字串、纯账号误伤为隐私。

**其它特殊处理**：
- **@提及**：群聊里 `@昵称 ` 一律替换为 `@某同学`；显示名内部可能夹带空格甚至手机号（如 `@2201郑仲涵138...`），所以会一路吃到 ` `（四分之一空格）这个真实的提及分隔符为止（普通空格也会被一并吃掉）；`@所有人 / @全体成员` 公告语义保留。
- **wxid_ 前缀剥离**：群聊 CSV 内容开头的 `wxid_xxx:` / `xxx@chatroom:` 发送者前缀会被剥离，提取出的 wxid 反过来作为稳定的假名化 key。
- **#接龙整条丢弃**：报名接龙类含大量真实姓名的整条消息直接丢弃，不入库。

**发言者假名化**（`SpeakerPseudonymizer`，每个会话独立计数，跨会话不可关联）：
- 帖子作者 → `楼主`
- 评论者 → `同学A`、`同学B`、`同学C`...

### 5. 主入口 (ingest.py)

```bash
# 查看帮助
python ingest.py --help

# 校园墙 → 抽检文件(默认 dry-run，不写库)。--source 必填，无默认值
python ingest.py --source campus_wall --out out/campus.jsonl --limit 50

# 微信导出 → 抽检
python ingest.py --source wechat --wechat-file export.json --out out/wechat.jsonl

# 确认无误后灌入 campus-wall-ai（原 GraphRAG，端口 8011）
python ingest.py --source campus_wall --push
```

**参数说明**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--source` | **必填**（无默认） | 数据源：`campus_wall` 或 `wechat` |
| `--wechat-file` | `None` | 微信导出 JSON 路径（`--source wechat` 时必填） |
| `--out` | `out/units.jsonl` | dry-run 输出 JSONL 路径 |
| `--push` | `False` | 是否灌入 campus-wall-ai（原 GraphRAG，端口 8011；默认仅 dry-run 落文件） |
| `--graphrag-url` | `None` | 覆盖 `GRAPHRAG_URL` |
| `--batch-size` | `20` | 推送时每批文档数 |
| `--window` | `6` | 微信对话每个问题取其后多少条回复 |
| `--limit` | `None` | 最多处理多少条（调试用） |

## 使用流程

### 标准流程（推荐）

```bash
# 1. dry-run 模式提取数据
cd campus-wall-data-pipeline
python ingest.py --source campus_wall --out out/units.jsonl

# 2. 审查输出文件
# 打开 out/units.jsonl，检查数据质量
# 确认脱敏是否彻底、内容是否有价值

# 3. 确认无误后推送
python ingest.py --source campus_wall --push
```

### 全量更新流程

由于文档 id 由 `stable_id()`（source 的 SHA1 前 16 位）确定，重新推送会按 id 幂等覆盖，无需先清空，直接重跑即可：

```bash
# 重新推送全部数据（同 source 的文档会被原地覆盖刷新）
python ingest.py --source campus_wall --push
```

> 若确需删除已废弃的文档，可对单篇调 `DELETE /documents/{doc_id}`（doc_id 即 `ku_xxxx`）；campus-wall-ai（原 GraphRAG）未提供一次性清空所有文档的接口。

## 常见问题

### Q: 如何处理大量数据？

使用 `--limit` 参数分批处理：

```bash
# 先处理 100 条测试
python ingest.py --source campus_wall --limit 100

# 确认无误后处理全部
python ingest.py --source campus_wall --push
```

### Q: 脱敏不彻底怎么办？

1. 检查 `desensitize.py` 的正则规则
2. 添加新的正则模式
3. 更新姓名花名册（NAME_BLACKLIST_FILE）
4. 重新 dry-run 验证

### Q: campus-wall-ai（原 GraphRAG）推送失败？

1. 检查 campus-wall-ai 服务是否运行：`curl http://localhost:8011/health`
2. 检查 `GRAPHRAG_URL` 配置
3. 检查网络连通性
4. 查看 campus-wall-ai 服务日志

### Q: 数据重复推送？

不会产生重复。每个 `KnowledgeUnit` 的文档 id 由 `stable_id()` 给出——对 `source`（如 `campus_wall:post:123`）取 SHA1 前 16 位并加 `ku_` 前缀。相同 source 多次灌入会落到同一个 id，campus-wall-ai（原 GraphRAG）`/index` 按 id **幂等覆盖**（不是按向量相似度去重），因此重复运行只是刷新同一篇文档，安全可重入。
