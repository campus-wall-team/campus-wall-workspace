# campus-wall-data-pipeline 开发文档

## 项目简介

campus-wall-data-pipeline 是校园墙项目的数据处理管道，负责从 campus_wall 的 MySQL 数据库中提取帖子和评论数据，经过清洗、脱敏处理后，推送到 campus-wall-graphrag 服务构建知识图谱，为 AI 学长问答提供知识支撑。

**设计原则**：
- **隐私优先**：默认 dry-run，人工审查后再推送
- **数据脱敏**：自动移除 PII 信息（手机号、身份证、姓名等）
- **可审计**：每个处理步骤都可追溯

### 2. 数据源适配器 (sources/)

#### campus_wall.py

从 campus_wall MySQL 提取数据：

```python
# 查询帖子和评论，组织为问答线程
SELECT p.id, p.title, p.content, p.user_id, p.create_time,
       c.id as comment_id, c.content as comment_content,
       c.user_id as comment_user_id
FROM post p
LEFT JOIN comment c ON p.id = c.post_id
WHERE p.status = 0 AND p.is_deleted = 0
ORDER BY p.create_time DESC
```

提取逻辑：
1. 查询已发布的帖子及其评论
2. 将帖子标题+内容作为"问题"
3. 将评论内容作为"回答"
4. 组织为 `KnowledgeUnit` 列表

### 3. 数据清洗 (clean.py)

清洗规则：

| 规则 | 说明 | 示例 |
|------|------|------|
| 规范化 | 统一空格、换行、标点 | 去除多余空格 |
| 噪声过滤 | 去除无意义内容 | "顶"、"沙发"、"UP" |
| 广告过滤 | 识别并过滤广告 | 含联系方式的推广 |
| 问候语过滤 | 去除开场问候 | "大家好"、"请问" |
| 问答检测 | 识别有效问答对 | 确保有问有答 |

### 4. 数据脱敏 (desensitize.py)

脱敏规则（正则匹配 + 替换）：

| 类型 | 正则模式 | 替换结果 |
|------|----------|----------|
| 手机号 | `1[3-9]\d{9}` | `****` |
| 身份证号 | `\d{17}[\dXx]` | `****` |
| 银行卡号 | `\d{16,19}` | `****` |
| 邮箱 | `[\w.-]+@[\w.-]+` | `****` |
| QQ 号 | `[Qq][Qq][:：]?\s*\d{5,11}` | `****` |
| 微信号 | `微信[:：]?\s*\w+` | `****` |
| 学号 | `\d{10,12}`（上下文判断）| `****` |
| 宿舍号 | `\d{1,2}[栋]-\d{3,4}` | `****` |

**发言者假名化**：
- 帖子作者 → `楼主`
- 评论者 → `同学A`、`同学B`、`同学C`...

### 5. 主入口 (ingest.py)

```bash
# 查看帮助
python ingest.py --help

# 默认 dry-run 模式（输出 JSONL 文件，不推送）
python ingest.py

# 指定数据源
python ingest.py --source campus_wall

# 推送到 GraphRAG（确认无误后执行）
python ingest.py --source campus_wall --push

# 指定输出文件
python ingest.py --output ./output/knowledge.jsonl
```

**参数说明**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--source` | `campus_wall` | 数据源：`campus_wall` 或 `wechat` |
| `--push` | `False` | 是否推送到 GraphRAG |
| `--output` | `./output/knowledge.jsonl` | dry-run 输出路径 |
| `--limit` | `None` | 限制处理条数 |



## 常见问题

### Q: 如何处理大量数据？

使用 `--limit` 参数分批处理：

```bash
# 先处理 100 条测试
python ingest.py --limit 100

# 确认无误后处理全部
python ingest.py --push
```

### Q: 脱敏不彻底怎么办？

1. 检查 `desensitize.py` 的正则规则
2. 添加新的正则模式
3. 更新姓名黑名单
4. 重新 dry-run 验证

### Q: GraphRAG 推送失败？

1. 检查 GraphRAG 服务是否运行：`curl http://localhost:8001/health`
2. 检查 `GRAPHRAG_URL` 配置
3. 检查网络连通性
4. 查看 GraphRAG 服务日志

### Q: 数据重复推送？

GraphRAG 的 `/index` 接口会基于内容去重（通过向量相似度），但建议在推送前清空旧数据或设计增量更新策略。
