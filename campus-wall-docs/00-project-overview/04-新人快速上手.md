# 新人快速上手

欢迎加入校园墙项目！本文档将帮助你在 30 分钟内完成环境搭建并运行项目。

## 环境要求

| 工具 | 最低版本 | 用途 | 安装方式 |
|------|----------|------|----------|
| JDK | 17 | Java 后端开发 | [Oracle JDK](https://www.oracle.com/java/technologies/downloads/) 或 [OpenJDK](https://adoptium.net/) |
| Maven | 3.8+ | Java 构建 | IDEA 内置 或 [官网下载](https://maven.apache.org/download.cgi) |
| Node.js | 18+ | 前端开发 | [官网下载](https://nodejs.org/) |
| Python | 3.12 | AI 服务开发 | [官网下载](https://www.python.org/downloads/) |
| Docker | 最新版 | 基础设施 | [Docker Desktop](https://www.docker.com/products/docker-desktop/) |
| Git | 最新版 | 版本控制 | [官网下载](https://git-scm.com/downloads) |
| IntelliJ IDEA | 最新版 | Java IDE | [官网下载](https://www.jetbrains.com/idea/download/) |
| VS Code | 最新版 | 前端/Python IDE | [官网下载](https://code.visualstudio.com/) |

**推荐配置**：
- 开发机内存：16GB+（同时运行多个服务 + Docker）
- 磁盘空间：50GB+（Docker 镜像、数据卷）

## 第一步：克隆代码

```bash
# 克隆主仓库（如果还有其他仓库，依次克隆）
git clone <仓库地址> campus_wall
git clone <仓库地址> campus-wall-frontend
git clone <仓库地址> campus-wall-monitor-ui
git clone <仓库地址> campus-wall-ai   # 原 campus-wall-graphrag 已并入
git clone <仓库地址> campus-wall-data-pipeline
git clone <仓库地址> campus-wall-alert-adapter
git clone <仓库地址> campus-wall-ops
```

**建议目录结构**：
```
campus-wall-workspace/
├── campus_wall/                  # 主后端
├── campus-wall-frontend/         # 多端前端
├── campus-wall-monitor-ui/       # 管理后台
├── campus-wall-ai/               # AI 服务（端口 8011，原 campus-wall-graphrag 已并入）
├── campus-wall-data-pipeline/    # 数据管道
├── campus-wall-alert-adapter/    # 告警适配
├── campus-wall-ops/              # 运维配置
└── docs/                         # 本文档目录
```

## 第二步：启动基础设施（Docker）

所有数据库和中间件通过 Docker Compose 一键启动：

```bash
cd campus-wall-ops

# 复制环境变量模板（按需修改）
cp .env.example .env

# 启动所有基础设施服务
docker-compose up -d
```

> **团队内网模式（推荐）**：实际开发中，中间件集中部署在本地 GB10 服务器（172.21.160.212），
> 前后端各自机器连内网开发，无需每人本机起一套。此时本步骤可跳过，改在各服务 .env 里把
> MySQL/Redis/MinIO/Neo4j 指向 GB10；Chat 模型走内网 Qwen3.6-35B（172.21.160.101:8003）。
> 详见 [20-operation/03 部署文档](../20-operation/)。下文仍给出单机本地启动方式，供离线/独立调试用。

**启动的服务**：
| 服务 | 端口 | 说明 |
|------|------|------|
| MySQL | 3306 | 主数据库 |
| Redis | 6379 | 缓存 |
| MinIO | 9000/9001 | 对象存储 |
| Neo4j | 7475/7688 | 知识图谱 |
| Prometheus | 9090 | 指标采集 |
| Grafana | 3000 | 可视化面板 |
| Alertmanager | 9093 | 告警管理 |
| Nginx | 8090 | 监控UI代理 |

**验证启动**：
```bash
# 查看所有容器状态
docker-compose ps

# 查看日志
docker-compose logs -f mysql
docker-compose logs -f redis
```

## 第三步：启动主后端服务 (campus_wall)

### 3.1 配置数据库

MySQL 首次启动后，数据库会自动通过 Flyway 迁移创建。检查数据库：

```bash
# 进入 MySQL 容器
docker exec -it campus-mysql mysql -uroot -p
# 密码在 .env 中，默认 123456

# 查看数据库
SHOW DATABASES;
USE campus_wall;
SHOW TABLES;
```

### 3.2 配置环境变量

```bash
cd campus_wall
cp .env.example .env
# 编辑 .env 文件，配置以下关键变量：
# - MySQL 连接信息
# - Redis 连接信息
# - MinIO 连接信息
# - 微信 AppID/AppSecret（如需微信登录）
# - graphrag.base-url（默认 http://localhost:8011，AI 学长走此地址；服务已并入 campus-wall-ai）
```

### 3.3 启动服务

**方式一：IDEA 启动（推荐开发时使用）**
1. IDEA 打开 `campus_wall` 项目
2. 等待 Maven 依赖下载完成
3. 运行 `CampusWallBackendApplication.java`
4. 服务将启动在 `http://localhost:8080`

**方式二：命令行启动**
```bash
cd campus_wall
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev
```

**验证启动**：
```bash
curl http://localhost:8080/actuator/health
# 预期返回：{"status":"UP"}
```

## 第六步：启动 AI 服务 (campus-wall-ai) [可选]

> 原独立服务 campus-wall-graphrag 已并入 campus-wall-ai（端口 8011），下文端点路径原样保留。

AI 问答功能需要启动 campus-wall-ai 服务。

### 6.1 启动 Ollama（本地三套模型：Chat / Embedding / VLM）

campus-wall-ai 默认**本地优先**，需拉取三个模型：

```bash
# 安装 Ollama (https://ollama.com/)
# 拉取 Embedding 模型（1024 维向量）
ollama pull bge-m3
# 拉取 Chat 模型（意图识别 / 答案合成 / 匹配理由）
ollama pull qwen2.5:7b
# 拉取 VLM 多模态模型（发带图帖时 describe_image 读图）
ollama pull qwen2.5vl:7b

# 启动 Ollama 服务（默认端口 11434）
# 若 campus-wall-ai 跑在容器里，需让 Ollama 监听所有网卡供容器访问：
OLLAMA_HOST=0.0.0.0 ollama serve
```

> **本地优先 + 云端降级**：campus-wall-ai 三套角色（chat / embed / vlm）都以本地 Ollama 为主。
> 各角色有独立的 `*_FALLBACK_ENABLED` 开关，开启后本地不可用时自动 failover 到云端 DashScope
> （Chat→qwen-plus、VLM→qwen-vl-plus；embed 降级默认关，需同模型同维）。
> 团队内网部署时，Chat 可改走内网 Qwen3.6-35B（172.21.160.101:8003）。

### 6.2 启动 campus-wall-ai

**方式一：Docker（推荐）**
```bash
cd campus-wall-ops
docker-compose up -d graphrag
```

**方式二：本地 Python**
```bash
cd campus-wall-ai

# 创建虚拟环境
python -m venv .venv

# Windows
.venv\Scripts\activate

# 安装依赖
pip install -r requirements.txt

# 配置环境变量
cp .env.example .env
# 编辑 .env：NEO4J_URI/USER/PASSWORD；
#   CHAT_*（本地 qwen2.5:7b）+ CHAT_FALLBACK_*（云端 qwen-plus）；
#   EMBED_*（bge-m3，EMBED_DIM=1024）；
#   VLM_*（qwen2.5vl:7b）+ VLM_FALLBACK_*（云端 qwen-vl-plus）；
#   BACKEND_BASE_URL（拼 /api/v1/files/view 取帖子图片）
# 注：端口 8011（campus-wall-ai 统一端口）

# 启动服务
uvicorn app.main:app --host 0.0.0.0 --port 8011
```

**验证启动**：
```bash
curl http://localhost:8011/health
# 预期返回 Neo4j 连接状态
```

## 第七步：验证完整链路

### 7.1 检查各服务状态

| 服务 | 验证地址 | 预期结果 |
|------|----------|----------|
| 主后端 | http://localhost:8080/actuator/health | `{"status":"UP"}` |
| 前端 H5 | http://localhost:5173 | 页面正常加载 |
| 管理后台 | http://localhost:5174 | 登录页面 |
| campus-wall-ai | http://localhost:8011/health | Neo4j 连接正常 |
| Prometheus | http://localhost:9090 | Web UI 正常 |
| Grafana | http://localhost:3000 | 登录页面（admin/admin） |
| MySQL | localhost:3306 | 可连接 |
| Redis | localhost:6379 | 可连接 |

### 7.2 测试一个完整功能

**测试发帖功能（5 板块）**：
1. 打开前端 H5 页面
2. 进入发布页面，选择板块：推荐 / 二手交易（填价格）/ 兼职发布（填薪资）/ 推广 / 组队
3. 填写内容、二级标签，上传图片
4. 点击发布
5. 在首页对应板块查看帖子是否出现

**测试 AI 学长帖子召回（/match-posts）**：
1. 确保已发布若干带图/带标签的帖子（已异步入图谱）
2. 打开 AI 学长聊天界面，用自然语言提问，如"有没有人出二手自行车"
3. 后端走单一入口 `POST /api/v1/ai-senior/agent`，agent 调 campus-wall-ai `/match-posts` 召回
4. 观察回答是否附带相关帖子卡片；无关帖应被 RelevanceJudge 过滤掉（反幻觉）

## 常用开发命令速查

### 后端 (campus_wall)

```bash
# 编译
mvn clean compile

# 运行测试
mvn test

# 打包
mvn clean package

# 运行（开发模式）
mvn spring-boot:run -Dspring-boot.run.profiles=dev
```

### 前端 (campus-wall-frontend)

```bash
# 安装依赖
npm install

# 开发模式（H5）
npm run dev:h5

# 开发模式（微信小程序）
npm run dev:mp-weixin

# 构建生产环境（H5）
npm run build:h5

# 类型检查
npm run type-check
```

### 管理后台 (campus-wall-monitor-ui)

```bash
# 安装依赖
npm install

# 开发模式
npm run dev

# 构建生产环境
npm run build
```

### Docker Compose (campus-wall-ops)

```bash
# 启动所有服务
docker-compose up -d

# 查看日志
docker-compose logs -f [服务名]

# 停止所有服务
docker-compose down

# 停止并删除数据卷（慎用）
docker-compose down -v

# 重启单个服务
docker-compose restart [服务名]

# 构建并启动
docker-compose up -d --build [服务名]
```
