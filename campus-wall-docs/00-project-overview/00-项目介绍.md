# 校园墙项目介绍

## 项目背景

校园墙是面向高校学生群体的匿名社交与信息交流平台，灵感来源于高校中广泛流传的"校园墙"文化。在传统模式下，校园墙通常由个人微信号运营，学生通过添加好友后发朋友圈或私聊来发布信息。这种模式存在信息分散、检索困难、管理不便等问题。

本项目旨在将这一校园社交场景数字化、系统化，打造一个集帖子发布、AI智能问答、实时私信、内容审核于一体的现代化校园社区平台。

## 项目愿景

> 让每一位大学生都能在一个安全、智能、有趣的社区中，自由地分享生活、获取信息、结识朋友。

## 核心功能模块

### 1. 圈子（帖子浏览与发布）
- 浏览校园内的匿名帖子，按 5 大板块筛选：推荐（recommend）、二手交易（secondhand，需填价格）、兼职发布（parttime，需填薪资）、推广（promotion）、组队（team）
- 板块下支持二级标签（tag）细分，便于精准检索
- 发布图文帖子，支持图片上传；二手已售置灰、推广 Banner 大图、组队报名/退出等场景化字段
- 点赞、收藏、评论互动
- 热帖排行榜（按本校/跨校/全省 + 日/周/月维度）与热搜榜

### 2. AI学长（智能问答助手）
- 基于 GraphRAG 知识图谱 + 大语言模型的智能问答
- 回答校园生活相关问题（选课、食堂、宿舍、社团等）
- 支持多轮对话，保留对话历史；具备短期上下文 + 长期用户记忆双层记忆
- 从校园历史帖子中提取知识构建知识图谱
- **Agent 编排能力**：单一入口 `POST /api/v1/ai-senior/agent`。默认（`ai.agent.remote-enabled=true`）转发到 campus-wall-ai 的 **LangGraph 图（Plan-Execute + 单次条件 replan）**；Java 进程内 Planner-Executor（规划 → 只读工具执行 → 严格接地合成）已降级为 `remote-enabled=false` 时的兜底实现
- **自然语言匹配并推送帖子**：理解用户需求后调 campus-wall-ai（端口 8011）`/match-posts` 召回相关帖子，并以卡片形式回填给前端
- **RelevanceJudge 反幻觉判定**：从严过滤召回结果，治好了"把无关帖当匹配硬答"的问题

### 3. 私信系统
- 用户间实时私信聊天
- 基于 WebSocket 的即时通讯
- 消息通知与未读提醒

### 4. 内容审核
- AI 自动审核 + 人工复审双机制
- 敏感词过滤
- 违规内容自动标记
- 管理后台审核队列

### 5. 用户系统
- 微信一键登录（OAuth2）
- 用户画像与偏好设置
- 浏览历史与收藏管理
- 关注/粉丝关系

### 6. 管理后台
- 独立 admin_user 账号体系 + RBAC 权限（superadmin / moderator / viewer 三预置角色，权限码 `module:action`）
- 内容审核面板、举报处理、意见反馈、学生认证复核
- 运营看板（KPI 卡 + 趋势/分布图表）与数据统计仪表盘（对接 Grafana）
- 用户管理（封禁/解封）、管理员与角色权限管理、系统配置
- 操作审计日志、系统监控概览

## 目标用户

**主要用户**：在校大学生
- 需要发布信息（二手交易、兼职、推广、组队等）
- 需要获取校园生活信息
- 希望匿名表达（吐槽、求助、推荐）
- 需要智能问答辅助

**管理员**：校园墙运营团队
- 审核发布内容
- 处理用户反馈
- 监控系统运行状态

## 项目特点

| 特点 | 说明 |
|------|------|
| **前后端分离** | Java 后端 + Vue 前端，独立开发、独立部署 |
| **微服务架构** | 6个独立仓库，职责清晰，可独立迭代 |
| **AI 驱动** | 集成大语言模型，GraphRAG 知识图谱检索 |
| **多端支持** | 基于 uni-app，一套代码支持 H5、微信小程序等多端 |
| **可观测性** | 完整的 Prometheus + Grafana + Alertmanager 监控告警体系 |
| **数据隐私** | ETL 数据管道支持数据脱敏，保护用户隐私 |

## 技术亮点

1. **GraphRAG 知识图谱**：将校园历史帖子转化为 Neo4j 知识图谱，结合 Neo4j 原生向量索引实现精准问答
2. **按角色分配的多模型架构**：Chat（规划/合成/判定/意图/抽取）主用**团队内网 Qwen3.6-35B**（@172.21.160.101:8003，`CHAT_MODEL=Qwen3.6-35B`），云端 DashScope（qwen-plus）作 failover 但默认关闭（`CHAT_FALLBACK_ENABLED=False`，与 Java agent 行为一致：.101 宕则不可用）；Embedding 走本地 `bge-m3`（1024 维，锁定）、VLM 走本地 `qwen2.5vl:7b`，二者云端兜底（qwen-vl-plus）默认开启——即仅 Embedding/VLM 为本地优先，Chat 以内网 35B 为主
3. **VLM 多模态读图**：发带图帖时由 VLM `describe_image` 生成图片文字描述，连同帖子文本一并入图谱，让"看图"也能被检索匹配
4. **AI 学长 Agent 反幻觉**：单一 `/api/v1/ai-senior/agent` 入口，默认转发到 campus-wall-ai 的 LangGraph 图（Plan-Execute + 单次条件 replan，Java agent 为兜底）+ RelevanceJudge 严格判定，杜绝无关帖误匹配
5. **内容安全**：AI 复审 + 敏感词过滤 + 人工审核三层防护，发帖前 PII 脱敏
6. **可观测平台**：十余个 Docker 服务（中间件 + AI 服务 + 监控告警栈）组成的完整可观测体系

## 项目规模

- **6个代码仓库**，涵盖后端、前端、AI、数据、运维全链路
- **后端**：~160个 Java 源文件，Spring Boot 3 + MyBatis-Plus
- **前端**：~80个文件，uni-app 跨端框架，30个页面
- **AI 服务**：campus-wall-ai（端口 8011，Python FastAPI + Neo4j GraphRAG，原 campus-wall-graphrag 已并入）
- **基础设施**：MySQL、Redis、MinIO、Neo4j、Prometheus、Grafana
