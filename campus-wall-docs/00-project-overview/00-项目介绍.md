# 校园墙项目介绍

## 项目背景

校园墙是面向高校学生群体的匿名社交与信息交流平台，灵感来源于高校中广泛流传的"校园墙"文化。在传统模式下，校园墙通常由个人微信号运营，学生通过添加好友后发朋友圈或私聊来发布信息。这种模式存在信息分散、检索困难、管理不便等问题。

本项目旨在将这一校园社交场景数字化、系统化，打造一个集帖子发布、AI智能问答、实时私信、内容审核于一体的现代化校园社区平台。

## 项目愿景

> 让每一位大学生都能在一个安全、智能、有趣的社区中，自由地分享生活、获取信息、结识朋友。

## 核心功能模块

### 1. 圈子（帖子浏览与发布）
- 浏览校园内的匿名帖子，按分类筛选（失物招领、二手交易、表白墙、求助问答等）
- 发布图文帖子，支持图片上传
- 点赞、收藏、评论互动
- 热帖排行榜

### 2. AI学长（智能问答助手）
- 基于 GraphRAG 知识图谱 + 大语言模型的智能问答
- 回答校园生活相关问题（选课、食堂、宿舍、社团等）
- 支持多轮对话，保留对话历史
- 从校园历史帖子中提取知识构建知识图谱

### 3. 私信系统
- 用户间实时私信聊天
- 基于 WebSocket 的即时通讯
- 消息通知与未读提醒

### 4. 内容审核
- AI 自动审核 + 人工复审双机制
- 敏感词过滤
- 违规内容自动标记
- 管理后台审核队列

### 5. 用户系统
- 微信一键登录（OAuth2）
- 用户画像与偏好设置
- 浏览历史与收藏管理
- 关注/粉丝关系

### 6. 管理后台
- 内容审核面板
- 数据统计仪表盘（对接 Grafana）
- 用户管理
- 系统监控概览

## 目标用户

**主要用户**：在校大学生
- 需要发布信息（失物招领、二手交易、活动宣传）
- 需要获取校园生活信息
- 希望匿名表达（表白、吐槽、求助）
- 需要智能问答辅助

**管理员**：校园墙运营团队
- 审核发布内容
- 处理用户反馈
- 监控系统运行状态

## 项目特点

| 特点 | 说明 |
|------|------|
| **前后端分离** | Java 后端 + Vue 前端，独立开发、独立部署 |
| **微服务架构** | 7个独立仓库，职责清晰，可独立迭代 |
| **AI 驱动** | 集成大语言模型，GraphRAG 知识图谱检索 |
| **多端支持** | 基于 uni-app，一套代码支持 H5、微信小程序等多端 |
| **可观测性** | 完整的 Prometheus + Grafana + Alertmanager 监控告警体系 |
| **数据隐私** | ETL 数据管道支持数据脱敏，保护用户隐私 |

## 技术亮点

1. **GraphRAG 知识图谱**：将校园历史帖子转化为 Neo4j 知识图谱，结合向量检索实现精准问答
2. **双 LLM 架构**：Chat LLM（DashScope/qwen-plus）+ Embedding LLM（本地 Ollama/bge-m3），兼顾效果与成本
3. **内容安全**：AI 复审 + 敏感词过滤 + 人工审核三层防护
4. **可观测平台**：16个 Docker 容器组成的完整监控告警体系

## 项目规模

- **7个代码仓库**，涵盖后端、前端、AI、数据、运维全链路
- **后端**：~160个 Java 源文件，Spring Boot 3 + MyBatis-Plus
- **前端**：~80个文件，uni-app 跨端框架，30个页面
- **AI 服务**：Python FastAPI + Neo4j GraphRAG
- **基础设施**：MySQL、Redis、MinIO、Neo4j、Chroma、Prometheus、Grafana
