# campus_wall 开发文档

## 项目简介

campus_wall 是校园墙项目的核心业务后端服务，负责处理所有业务逻辑，包括用户认证、帖子管理、评论系统、AI 聊天代理、内容审核、私信系统等。

## 开发环境搭建

### 1. 环境要求

- JDK 17+
- Maven 3.8+（或 IDEA 内置）
- MySQL 8.0
- Redis 7.0
- MinIO

### 2. 启动基础设施

```bash
cd campus-wall-ops
docker-compose up -d mysql redis minio
```

### 3. 配置环境变量

```bash
cd campus_wall
cp .env.example .env
# 编辑 .env，配置数据库、Redis、MinIO 连接信息
```

### 4. IDEA 启动

1. IDEA 打开 `campus_wall` 文件夹
2. 等待 Maven 依赖下载
3. 运行 `CampusWallBackendApplication`
4. 访问 `http://localhost:8080/actuator/health`

### 5. 命令行启动

```bash
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev
```

## 核心模块说明

### 1. 认证模块 (common/util/JwtUtil + social)

- **JwtUtil**：JWT Token 生成与验证
- **Interceptor**：请求拦截，验证 Token
- 微信 OAuth2 登录流程：前端获取 code → 后端调用微信接口换取 openid → 生成 JWT Token

### 2. 社区模块 (community)

- **PostController**：帖子 CRUD、点赞、收藏、热帖、组队加入/退出
- **CommentController**：评论发表、列表、删除
- **CategoryController**：分类管理
- **SearchController**：帖子搜索
- **RankController**：排行榜（热帖榜 + 热搜榜）

核心实体：
- `Post`：帖子（id, userId, categoryId, boardType, title, content, images, viewCount, likeCount, status, is_top, price, salary, info_fee, contact, banner_object_name, is_sold...）
- `Comment`：评论（id, postId, userId, content, parentId...）
- `Category`：分类（id, name, sortOrder...）

**板块分类 `BoardType` 枚举（5 值，community/enums）**：

| 枚举 | code | 名称 | 约束 |
|------|------|------|------|
| RECOMMEND | recommend | 推荐 | - |
| SECONDHAND | secondhand | 二手交易 | requirePrice（price=NULL 表面议；is_sold 已售置灰）|
| PARTTIME | parttime | 兼职发布 | requireSalary（salary、info_fee 信息费）|
| PROMOTION | promotion | 推广 | banner_object_name 推广 Banner 大图 |
| TEAM | team | 组队 | team_member / team_max_members |

发现页区域筛选：`GET /api/v1/posts/list` 支持 `scope`/`campus`/`regionScope`/`locationKeywords` 参数（基于 post_campus 表）。

### 3. AI 模块 (ai)

AI 已收口为**单一入口 Agent**，采用轻量 **Planner-Executor** 架构，并配备反幻觉判定闸与双层对话记忆。旧的 `ChatController` / `SeniorAssistantService` 及"接收问题→保存→调 GraphRAG /query→保存回复"的线性流程已下线。

- **AgentController**：`POST /api/v1/ai-senior/agent`，唯一对话入口。`@RequestAttribute("userId")` 强制 JWT 鉴权（不再从 DTO 取 userId）。返回 `{success, answer, posts(匹配帖子卡片), plan(调试), conversationId}`。
- **AiSeniorController**：现仅剩 `knowledge/*`（import / batch-import / list / {id} 删 / import-text / clear）+ `history/*`（list / detail）。
- **AiPreferenceController**：`GET /ai-preference/get`、`POST /ai-preference/save`、`GET /ai-preference/system-prompt`。

**Agent 编排流程（`ai.agent` 包：engine / tool / plan / service）**：
1. 读短期记忆（`ConversationMemoryService`，落 `ai_chat_record`）
2. 指代消解（`QuestionContextualizer`，补全"它/那个"等指代）
3. 规划（`Planner`，决定调用哪些只读工具）
4. 执行工具（`ToolExecutor` → `ToolRegistry`：`SearchPostsTool` 调 campus-wall-ai（端口 8011，原 graphrag 服务已并入）`POST /match-posts` 找帖；`KnowledgeQaTool` 调 campus-wall-ai `POST /query` 查知识库）
5. **反幻觉判定（`RelevanceJudge`）**：用 Spring AI 结构化输出收 `List<Long>`（裸 postId 数组），从严判定只放行真正相关的帖子，治好了 match-posts 把无关帖当匹配的瞎答问题
6. 严格接地合成（`Synthesizer`，只基于判定通过的证据生成答案）
7. 异步沉淀长期记忆（`ai.memory`：`MemoryExtractor.extractAsync` 抽取，存 `ai_user_memory` 表，由 `AiUserMemoryService` 管理）

**与 campus-wall-ai 的交互**（原 graphrag 服务已并入 campus-wall-ai，端口 8011）：agent 经 `GraphRagBackend`（实现 `IRagBackend`，`graphrag.base-url` 默认 `http://localhost:8011`）调用 `POST /match-posts`（找帖）与 `POST /query`（知识库问答）；发帖时异步入图谱 `POST /ingest-post`；知识库导入 `POST /index`。

### 4. 社交模块 (social)

- **UserController**：用户信息、登录
- **FollowController**：关注/取消关注
- **MessageController**：私信（REST API + WebSocket）
- **NotificationController**：消息通知

WebSocket 私信：
- 连接地址：`ws://host/ws/chat`
- 认证方式：Header 携带 `Authorization: Bearer <token>`
- 消息格式：`{ type, toUserId, content, timestamp }`

### 5. 管理模块 (admin)

管理端为**物理隔离的独立 `admin_user` 账号体系 + RBAC**（不是给 C 端 `user` 加 `role` 字段）。后端是鉴权权威。

**RBAC 模型（V4.0/V4.1）**：5 张表 `admin_user` / `admin_role` / `admin_permission` / `admin_user_role` / `admin_role_permission`；3 个预置角色：`superadmin`（全权）/ `moderator`（内容审核员）/ `viewer`（只读运营）；权限码形如 `module:action`（如 `moderation:queue`、`stat:view`、`user:ban`、`role:assign`、`sys:config`、`audit:view`）。

**鉴权链路**：`AdminAuthInterceptor` + 方法级 `@RequirePermission(权限码)` + `AdminJwtUtil`（独立 admin token，与 C 端 JWT 隔离）。

**Controller**：
- **AdminAuthController**：`POST /admin/login`（查 `admin_user` 签发 admin token，BCrypt 校验）、`GET /admin/auth/me`、`POST /admin/auth/logout`。登录已从 `AdminModerationController` 迁出。
- **AdminModerationController**：`moderation/queue`、`scan`、`{id}/approve`、`{id}/reject`、`GET /admin/stats`（瞬时卡片，与运营看板 stat/* 并存），均需 `@RequirePermission`。
- **AdminReportController**：举报处理。
- **AdminFeedbackController**：意见反馈处理。
- **AdminStudentVerificationController**：学生认证人工复核（`/admin/verification` list / review）。
- **AdminUserMgmtController**：`/admin/users` C 端用户封禁/解封。
- **AdminManageController**：管理员/角色/权限 CRUD（`/admin/admins`、`/roles`、`/permissions`、`/roles/{id}/permissions`）。
- **StatController**（运营看板）：`/admin/stat/{overview,trend,active,distribution,top-posts}`（`stat:view`）。配 `stat_daily` 每日快照表（V4.3，DAU 用 HLL 去重）。
- **AdminSysConfigController**：`GET/PUT /admin/configs`（`sys:config` / `sys:config-save`）。配 `sys_config` 表（V4.4）。
- **AuditLogController**：`GET /admin/audit`（`audit:view`）。

**操作审计**：`@OperationLog` AOP 切面（`admin.audit` 包）拦截管理操作 → 写入 `admin_oper_log` 表（V4.2）。

> ⚠️ 旧文档"管理员缺角色体系 / 无 `User.role` 鉴权 / 任何登录用户可访问管理接口"的说法已全部作废。

### 6. 内容审核

三层审核机制：
1. **敏感词过滤**：加载 `sensitive-words.txt`，DFA 算法匹配
2. **AI 复审**：命中可疑规则时，调用本地 `qwen2.5:7b` 判定
3. **人工审核**：AI 不确定的内容进入管理后台审核队列（`@RequirePermission(moderation:queue)`）

配置项（`application.yaml`）：
```yaml
moderation:
  sensitive-words-path: classpath:sensitive-words.txt
  ai-rescore-enabled: true
```

### 7. 缓存模块 (common/util/RedisUtil)

缓存策略：

| 缓存 Key | 过期时间 | 说明 |
|----------|----------|------|
| `user:info:{userId}` | 2小时 | 用户信息 |
| `post:detail:{postId}` | 30分钟 | 帖子详情 |
| `post:list:{category}:{page}` | 5分钟 | 帖子列表 |
| `comment:list:{postId}` | 10分钟 | 评论列表 |
| `hot:posts` | 10分钟 | 热帖列表 |
| `user:stats:{userId}` | 30分钟 | 用户统计 |

### 8. 定时任务 (task)

- **MetricsCollectionTask**：收集业务指标（ Prometheus 自定义指标）
- **FileCleanupTask**：清理过期临时文件

## 常见问题

### Q: Maven 依赖下载慢？

在 `pom.xml` 或 `~/.m2/settings.xml` 中配置阿里云镜像：

```xml
<mirror>
    <id>aliyunmaven</id>
    <mirrorOf>*</mirrorOf>
    <name>阿里云公共仓库</name>
    <url>https://maven.aliyun.com/repository/public</url>
</mirror>
```

### Q: Flyway 迁移失败？

1. 检查数据库连接是否正常
2. 检查 `db/migration/` 下的 SQL 语法
3. 如需重置，删除 Flyway 历史表：`DELETE FROM flyway_schema_history;`

### Q: Redis 连接失败？

检查 `application-dev.yaml` 中的 Redis 配置，确保密码正确。

### Q: 上传图片失败？

1. 检查 MinIO 是否正常运行
2. 检查 MinIO 配置（endpoint, accessKey, secretKey）
3. 检查 bucket 是否已创建
