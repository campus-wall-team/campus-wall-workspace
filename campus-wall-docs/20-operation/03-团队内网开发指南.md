# 团队内网开发指南（中间件部署在本地 GB10 服务器）

> 本指南说明团队如何在**同一局域网**下协作开发 Campus Wall：所有**中间件**集中部署在一台本地服务器（NVIDIA GB10），**前端 / 后端**在各成员自己的电脑上开发，连接服务器上的中间件即可跑通整个 demo。
>
> 适用：团队成员都在**同一办公室/实验室局域网**。需要远程接入时见文末「扩展」。
>
> **最近更新：2026-06-15**

---

## 1. 架构与角色

```
   开发成员电脑（多台）                    GB10 中间件服务器（一台，172.21.160.212）
┌────────────────────┐                 ┌──────────────────────────────────────────┐
│ 前端 uni-app        │  HTTP/WS        │  campus-wall-ai :8011（AI 学长，连本机 Ollama）│
│  → 连自己的后端       │ ──────────────► │  Ollama（qwen2.5:7b + bge-m3 + qwen2.5vl:7b │
│                     │                 │         GB10 GPU；qwen2.5vl 为图片理解 VLM）│
│ 后端 Spring :8080    │   局域网直连     │  ┌── Docker 中间件（自启 unless-stopped）─┐ │
│  → 连服务器中间件     │ ══════════════► │  │ MySQL · Redis · MinIO · Neo4j          │ │
└────────────────────┘                 │  │ Prometheus · Grafana · Alertmanager    │ │
                                        │  └────────────────────────────────────────┘ │
                                        └──────────────────────────────────────────────┘
```

| 角色 | 在哪 | 干什么 |
|------|------|--------|
| **中间件服务器** | GB10（`172.21.160.212`） | 跑 MySQL/Redis/MinIO/Neo4j/campus-wall-ai/监控；常开机、自启；只需 1 台 |
| **开发成员** | 各自电脑 | 跑后端 + 前端，连服务器中间件做开发 |

> 为什么放本地不放阿里云：GB10 自带 GPU（121G 内存），本地离线跑大模型又快又免费；内网零公网暴露、零云费用。等需要「对外公网访问」时再上云（见文末）。

## 3. 【开发成员】五步跑通

### 第 0 步：前置
- 装好 JDK 17+、Maven（或用项目自带 `./mvnw`）、Node.js 18+、Git；后端开发用微信小程序还需微信开发者工具。
- 确认你和服务器在**同一局域网**。

### 第 1 步：克隆工作区（含子模块）
```bash
git clone --recurse-submodules git@github.com:campus-wall-team/campus-wall-workspace.git
cd campus-wall-workspace
# 若子目录为空：git submodule update --init --recursive
```

### 第 2 步：自检能否连到服务器
```bash
bash deploy/team-dev/check-connection.sh
# 全绿 → 继续；有红 → 按提示排查（同网段 / 服务器是否在跑 / IP 是否变）
```

### 第 3 步：配置并启动后端
```bash
# 1) 复制后端配置模板，填入真实密钥（密钥向管理员索取）
cp deploy/team-dev/backend.env.example campus_wall/.env
#    用编辑器把 <向管理员索取> 的几项填上；若服务器 IP 变了，同步改 IP

# 2) 启动后端（开发模式，:8080）
cd campus_wall
./mvnw spring-boot:run
#    或用已构建的 jar： java -jar target/campus-wall-0.0.1-SNAPSHOT.jar

# 3) 验证后端起来了
curl http://localhost:8080/actuator/health    # {"status":"UP"}
```
> 后端会连服务器上的 MySQL/Redis/MinIO/campus-wall-ai。首次启动 Flyway 会校验/迁移数据库（数据库已建好，正常跳过）。

### 第 4 步：配置并启动前端
```bash
cp deploy/team-dev/frontend.env.development.example campus-wall-frontend/.env.development
#    VITE_API_BASE_URL 指向你自己的后端（H5 用 localhost:8080；微信真机用你本机局域网 IP）
cd campus-wall-frontend
npm install
npm run dev:h5            # 浏览器预览；或 npm run dev:mp-weixin 进微信开发者工具
```

### 第 5 步：端到端验证「AI 学长」
登录拿 token 后调 AI 接口（也可在前端 AI 页面直接问）：
```bash
# 用管理员账号拿 JWT（账号密码向管理员索取）
TOKEN=$(curl -s -X POST http://localhost:8080/api/v1/admin/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"<管理员密码>"}' | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")

# 问 AI 学长（后端 → 服务器 campus-wall-ai → 答案）
# AI 已收口为单一入口 /api/v1/ai-senior/agent；userId 从 JWT 取，不再放进 body
curl -X POST http://localhost:8080/api/v1/ai-senior/agent \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"question":"图书馆几点关门？","conversationId":null}'
# 预期返回 success:true + answer + posts（匹配帖子卡片）+ conversationId
```

✅ 到这里你就在自己的电脑上跑通了完整 demo，可以开始开发。

## 5. 【服务器管理员】维护手册

> 中间件已部署在 GB10 并设为 `restart=unless-stopped`（开机自启、崩溃自启），日常无需干预。

**查看状态：**
```bash
docker ps | grep '^campus-'                 # 中间件容器
curl http://localhost:8011/health           # campus-wall-ai
hostname -I                                  # 当前局域网 IP（变了要通知团队）
```

**AI 服务（host 直跑）：**

> 原 GraphRAG 独立服务已并入 campus-wall-ai（端口 8011）；下方为原 GraphRAG 的 host 直跑方式（历史参考），现以 campus-wall-ai 单服务运行。

```bash
# 手动启动（后台）
cd /home/nvidia/Desktop/campus-wall
nohup bash demo/run-graphrag.sh >> demo/logs/graphrag.log 2>&1 & disown
# 或装成开机自启服务（推荐，见文件内说明）
sudo cp deploy/server/campus-graphrag.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now campus-graphrag
```

**给团队分发后端密钥（不进 git）：**
```bash
bash deploy/server/export-team-env.sh        # 生成 deploy/team-dev/backend.env（含真实密钥，已被 gitignore）
# 通过企业微信/钉钉/U盘发给队友，让其覆盖到 campus_wall/.env
```

**中间件容器编排说明：** 中间件已统一由仓库内的标准编排 [`campus-wall-ops/`](../../campus-wall-ops/) 启动，数据 **bind 挂载**在 `campus-wall-ops/data/{mysql,neo4j,minio}`。campus-wall-ai（AI 服务，端口 8011；已并入，原 GraphRAG 下线）仍为 host 直跑、`alert-adapter` 暂不启用（两者在 ops 编排里是 `build` 服务、本机不构建），故启动时指定服务清单：

```bash
cd campus-wall-ops
docker compose -f docker-compose.yml up -d \
  mysql redis minio neo4j \
  prometheus grafana alertmanager node-exporter redis-exporter mysqld-exporter blackbox-exporter monitor-ui
```

全栈数据层口令已**统一**（值见服务器 `campus-wall-ops/.env`；团队用的密钥由管理员通过 `backend.env` 分发——**口令若变更，务必重发新的 `backend.env`**）。**请勿 `docker compose down -v`**（会删数据卷）。换新机器 / 上云时，同一套 `campus-wall-ops` 编排通用，把 `campus-wall-ops/data` 一并迁移即可。

## 6. 常见问题

| 现象 | 原因 / 解决 |
|------|-------------|
| `check-connection.sh` 全红 | 不在同一局域网；或服务器中间件没跑；或服务器 IP 变了（传新 IP 重试） |
| 后端启动报 `UnsupportedEncodingException: utf8mb4` | `.env` 的 `characterEncoding` 要用 `utf8`，不要 `utf8mb4` |
| 后端报 Flyway 校验失败 | 加启动参数 `--spring.flyway.validate-on-migrate=false`，或联系管理员修复迁移历史 |
| AI 学长无响应 / 超时 | 服务器 campus-wall-ai（8011，已并入，原 GraphRAG 下线）或 Ollama 没跑；管理员查 `curl localhost:8011/health` 与 `ollama list` |
| 微信真机连不上后端 | 前端 `VITE_API_BASE_URL` 不能用 `localhost`，要用你本机的**局域网 IP** |
| 连不上 MinIO / 文件上传失败 | 确认服务器 `campus-minio` 在跑；demo 主链路不依赖文件上传 |

## 7. 扩展：以后需要「远程 / 对外访问」时

- **个别成员远程**：给 GB10 装轻量内网穿透（Tailscale / WireGuard / frp），队友在外网也能安全连回服务器，**仍免云费用、保留 GPU**。
- **对外公网正式 demo / 上线**：把中间件迁到阿里云 ECS，届时做安全加固（数据库端口不暴露公网、走隧道/白名单、Chat 用 DashScope 或 GPU 实例）。同一套 `campus-wall-ops` 编排两边通用。
