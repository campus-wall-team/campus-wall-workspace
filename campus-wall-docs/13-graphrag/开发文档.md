# campus-wall-graphrag 开发文档

## 项目简介

campus-wall-graphrag 是校园墙项目的 AI 问答核心引擎，基于 GraphRAG（Graph Retrieval-Augmented Generation）技术，将校园历史帖子转化为 Neo4j 知识图谱，结合向量检索和大语言模型，为用户提供精准的校园生活问答服务。

**核心能力**：
- 文档索引：接收校园文档，提取实体关系，构建知识图谱
- 知识问答：基于知识图谱 + 向量检索回答用户问题
- 双 LLM 架构：Chat LLM 负责推理，Embedding LLM 负责向量化

## 开发环境搭建

### 1. 环境要求

- Python 3.12
- Neo4j 5（通过 Docker）
- Ollama（本地 Embedding 服务）

### 2. 启动 Neo4j

```bash
cd campus-wall-ops
docker-compose up -d neo4j
```

Neo4j 管理界面：`http://localhost:7475`
- 用户名：`neo4j`
- 密码：`.env` 中配置的 `NEO4J_PASSWORD`

### 3. 启动 Ollama

```bash
# 安装 Ollama: https://ollama.com/

# 拉取 bge-m3 模型
ollama pull bge-m3

# 启动服务
ollama serve
```

Ollama API：`http://localhost:11434`

### 4. 安装 Python 依赖

```bash
cd campus-wall-graphrag

# 创建虚拟环境
python -m venv .venv

# Windows
.venv\Scripts\activate

# 安装依赖
pip install -r requirements.txt
```

### 5. 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env`：

```env
# Neo4j
NEO4J_URI=bolt://localhost:7688
NEO4J_USER=neo4j
NEO4J_PASSWORD=your_password

# Chat LLM (DashScope)
CHAT_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
CHAT_API_KEY=your_dashscope_api_key
CHAT_MODEL=qwen-plus

# Embedding LLM (Ollama)
EMBED_BASE_URL=http://localhost:11434/v1
EMBED_API_KEY=ollama
EMBED_MODEL=bge-m3
EMBED_DIM=1024

# 服务端口
GRAPHRAG_PORT=8001
```

### 6. 启动服务

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8001 --reload
```

访问 API 文档：`http://localhost:8001/docs`（Swagger UI）

## 核心模块说明

### 1. 配置模块 (config.py)

支持双 LLM 独立配置：

```python
# Chat LLM 配置（推理）
CHAT_BASE_URL     # Chat API 地址
CHAT_API_KEY      # Chat API 密钥
CHAT_MODEL        # Chat 模型（默认 qwen-plus）

# Embedding LLM 配置（向量化）
EMBED_BASE_URL    # Embedding API 地址
EMBED_API_KEY     # Embedding API 密钥
EMBED_MODEL       # Embedding 模型（默认 bge-m3）
EMBED_DIM         # 向量维度（默认 1024）
```

**向下兼容**：如果 `CHAT_*`/`EMBED_*` 未设置，自动回退到旧版 `LLM_*` 变量。

### 2. 图存储模块 (graph_store.py)

Neo4j 操作封装：

```python
class Neo4jStore:
    # 连接管理
    def __init__(self, uri, user, password)

    # 文档索引
    def index_document(text, metadata)     # 索引文档
    def index_documents(documents)         # 批量索引

    # 向量检索
    def search_similar(query_vector, top_k=5)  # 相似度搜索

    # 图查询
    def get_entity_relations(entity_id)    # 获取实体关系
    def traverse_graph(start_node, depth)  # 图遍历

    # 管理
    def clear_all()                        # 清空图谱
    def get_stats()                        # 统计信息
```

**图模型**：
- `Document`：原始文档节点
- `Chunk`：文档分块节点（带向量嵌入）
- `Entity`：抽取的实体节点
- `RELATES_TO`：实体间关系
- `CONTAINS`：文档包含分块

### 3. LLM 模块 (llm.py)

双客户端设计：

```python
# Chat 客户端（推理）
chat_client = OpenAI(
    base_url=CHAT_BASE_URL,
    api_key=CHAT_API_KEY
)

# Embedding 客户端（向量化）
embed_client = OpenAI(
    base_url=EMBED_BASE_URL,
    api_key=EMBED_API_KEY
)
```

**Chat 调用**：
```python
response = chat_client.chat.completions.create(
    model=CHAT_MODEL,
    messages=[...],
    temperature=0.7
)
```

**Embedding 调用**：
```python
response = embed_client.embeddings.create(
    model=EMBED_MODEL,
    input=text
)
vector = response.data[0].embedding  # 1024 维向量
```

### 4. API 端点 (main.py)

#### GET /health
健康检查，返回 Neo4j 连接状态。

#### POST /index
索引文档到知识图谱。

**请求**：
```json
{
  "documents": [
    {
      "text": "学校食堂二楼麻辣烫很好吃...",
      "metadata": { "source": "campus_wall", "post_id": 123 }
    }
  ]
}
```

**响应**：
```json
{
  "indexed": 1,
  "chunks": 3,
  "entities": 5
}
```

#### POST /query
知识问答。

**请求**：
```json
{
  "question": "学校食堂有什么好吃的？",
  "history": [
    { "role": "user", "content": "..." },
    { "role": "assistant", "content": "..." }
  ]
}
```

**响应**：
```json
{
  "answer": "根据同学们的分享，学校食堂二楼的麻辣烫和三楼的面食比较受欢迎...",
  "sources": [
    { "text": "...", "score": 0.92 }
  ]
}
```

#### GET /documents
获取已索引的文档列表。

## GraphRAG 工作原理

### 索引流程

```
原始文档
    │
    ▼
文档分块 (chunking)
    │
    ├──► 实体关系抽取 (LLM)
    │    "食堂" --位于--> "二楼"
    │    "麻辣烫" --属于--> "食堂"
    │
    ├──► 向量化 (Embedding)
    │    "学校食堂二楼麻辣烫很好吃"
    │    → [0.1, -0.3, 0.8, ...] (1024维)
    │
    ▼
写入 Neo4j
    ├── Document 节点
    ├── Chunk 节点（带向量索引）
    ├── Entity 节点
    └── 关系边
```

### 查询流程

```
用户问题
    │
    ▼
向量化 (Embedding)
    │
    ▼
向量检索 (Neo4j)
    找到最相似的 Chunk 节点
    │
    ▼
图遍历 (Neo4j)
    获取相关 Entity 和关系
    │
    ▼
构造 Prompt
    检索结果 + 历史对话 + 用户问题
    │
    ▼
生成回答 (Chat LLM)
    DashScope/qwen-plus
    │
    ▼
返回格式化回答
```

## 配置切换：本地 Chat LLM

当前 Chat LLM 使用 DashScope（云端），可以切换为本地 Qwen：

1. 编辑 `.env`：
```env
CHAT_BASE_URL=http://host.docker.internal:11434/v1
CHAT_MODEL=qwen3.5-397b
CHAT_API_KEY=any-placeholder
```

2. 重启服务：
```bash
docker-compose up -d --build graphrag
```

Embedding 不受影响。

## 常见问题

### Q: Neo4j 连接失败？

1. 检查 Neo4j 容器是否运行：`docker ps | grep neo4j`
2. 检查 Neo4j 端口：`localhost:7475` (HTTP) / `localhost:7688` (Bolt)
3. 检查密码是否正确

### Q: Ollama Embedding 失败？

1. 检查 Ollama 是否运行：`curl http://localhost:11434/api/tags`
2. 检查 bge-m3 是否已拉取：`ollama list`
3. 容器内访问 Ollama 需要使用 `host.docker.internal:11434`

### Q: 向量维度不匹配？

确保 `EMBED_DIM` 与模型输出维度一致：
- bge-m3：1024 维
- 如更换模型，同步修改 `EMBED_DIM` 并重建向量索引

### Q: 回答质量不佳？

1. 检查知识图谱中是否有足够的数据
2. 调整向量检索的 `top_k` 值
3. 调整 Prompt 模板
4. 尝试更换 Chat LLM 模型
