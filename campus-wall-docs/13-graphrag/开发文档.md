# campus-wall-graphrag 开发文档

> ⚠️ 本服务已并入 campus-wall-ai（端口 8011），本目录作为历史/实现参考保留。

## 项目简介

campus-wall-graphrag 是校园墙项目的 AI 问答核心引擎，基于 GraphRAG（Graph Retrieval-Augmented Generation）技术，将校园历史帖子转化为 Neo4j 知识图谱，结合向量检索和大语言模型，为用户提供精准的校园生活问答服务。

**核心能力**：
- 文档索引：接收校园文档，提取实体关系，构建知识图谱
- 知识问答：基于知识图谱 + 向量检索回答用户问题（支持同步 `/query` 与 SSE 流式 `/query/stream`）
- 帖子知识入库：发帖后将「图片 + 文字 + 板块 + 标签」写入图谱（`/ingest-post`），图片走 VLM 读图，PII 入库前统一脱敏
- 智能推荐：自然语言诉求 → 意图识别 + 向量检索 + 匹配理由（`/match-posts`，如「丢了 X」匹配「捡到 X」）
- 三套 LLM 角色（chat / embed / vlm），统一**本地优先 + 云端降级（failover）**：本地 Ollama 为 primary，调用失败时自动降级到云端兜底，服务持续可用

### 2. 图存储模块 (graph_store.py)

Neo4j 操作封装（自实现，直接写 Cypher）：

```python
class GraphStore:
    def __init__(self)                     # 从 settings 建驱动
    def close(self)
    def ping(self) -> bool                 # /health 探活

    # schema：建唯一约束 + 两个向量索引
    def ensure_schema(self)

    # 文档知识库
    def index_document(title, content, source, doc_id) -> str  # 切块 + 嵌入 + 三元组抽取
    def search(question, top_k=5) -> list   # Chunk 向量检索 + 图谱事实 enrichment
    def list_documents() -> list
    def delete_document(doc_id) -> bool

    # 帖子知识图谱（07/08）
    def ingest_post(post_id, intent, category, text, images, tags) -> dict  # 读图+脱敏+入库
    def match_posts(question, intent, top_k=5) -> dict                      # 意图识别+向量检索+理由
    def delete_post(post_id) -> bool        # 删帖同步删 Post/Item
```

**图模型（文档知识库）**：
- `Document`：原始文档节点（id 唯一约束）
- `Chunk`：文档分块节点（带 1024 维向量嵌入）
- `Entity`：抽取的实体节点（name 唯一约束）
- `(Document)-[:HAS_CHUNK]->(Chunk)`：文档包含分块
- `(Document)-[:MENTIONS]->(Entity)`：文档提及实体
- `(Entity)-[:RELATED {type}]->(Entity)`：实体间关系（type 存谓词）

**图模型（帖子子图，07/08 新增）**：
- `Post`：帖子节点（postId 唯一约束，含 intent/category/text/status）
- `Item`：帖子物品节点（id 唯一约束，含 description/category/color/brand/model/features + 1024 维向量）
- `Intent` / `Category` / `Tag`：意图 / 板块 / 标签维度节点
- `(Post)-[:DESCRIBES]->(Item)`、`(Post)-[:HAS_INTENT]->(Intent)`、`(Post)-[:IN_CATEGORY]->(Category)`、`(Post)-[:TAGGED]->(Tag)`

**两个向量索引**（均 cosine，1024 维，互相独立不可复用）：
- `campus_chunk_vector`：`FOR (c:Chunk) ON (c.embedding)` — 文档问答检索
- `campus_post_vector`：`FOR (i:Item) ON (i.embedding)` — 帖子智能推荐检索

### 3. LLM 模块 (llm.py)

**三套角色 + 本地优先 / 云端降级（failover）**。每个角色有一个 primary 客户端（本地 Ollama）和一个可选 fallback 客户端（云端）。核心是 `_with_fallback(role, primary, fallback)`：先跑 primary，任何异常则自动降级到 fallback（启用时），fallback 未配则原异常透传——服务即使本地不可用也保持可用。

```python
# 三套角色（primary 本地 → fallback 云端）
# chat  : CHAT_BASE_URL / CHAT_MODEL(qwen2.5:7b) → CHAT_FALLBACK_*(qwen-plus，默认开)
# embed : EMBED_BASE_URL / EMBED_MODEL(bge-m3)    → EMBED_FALLBACK_*(默认关)
# vlm   : VLM_BASE_URL  / VLM_MODEL(qwen2.5vl:7b) → VLM_FALLBACK_*(qwen-vl-plus，默认开)

def _with_fallback(role, primary, fallback):
    try:
        return primary()
    except Exception:
        if fallback is None:
            raise
        return fallback()
```

> ⚠️ **embed 降级默认关闭**：向量已存 Neo4j，降级若用不同模型/维度，库内向量与查询向量将不兼容。chat / vlm 输出是文字，可自由换模型，无此约束。

**对外函数**：
- `chat(system, user, temperature=0.2)` / `chat_stream(...)`：答案合成，前者一次性、后者逐 token 流式（供 `/query/stream`）。
- `embed(texts)` / `embed_one(text)`：bge-m3 向量化，1024 维。
- `extract_triples(text)`：抽实体三元组（经 `chat()`，自动继承 failover）。
- `detect_intent(question)`：意图识别（lost_found / second_hand / part_time / team_up / daily）。
- `describe_image(image_url, user_text, intent)`：**VLM 读图**，对帖子图片做物体识别 / 结构化标注，返回 `{description, category, color, brand, model, features}`。`VLM_IMAGE_MODE=base64` 时先把图片下载成 base64（默认；`url` 模式则直接传 URL）。

### 4. API 端点 (main.py)

共 **9 个 HTTP 端点**，请求/响应字段以 `main.py` 的 Pydantic 模型为准。

#### GET /health
健康检查。响应 `{"status": "ok", "neo4j": true}`（`neo4j` 为连通性 ping 结果）。

#### POST /index
索引文档到知识图谱（切块 → 嵌入 → 三元组抽取，重复 id 会覆盖旧 Chunk/Entity）。

**请求**（`IndexRequest`）：
```json
{
  "documents": [
    { "id": "可选", "title": "食堂攻略", "content": "学校食堂二楼麻辣烫很好吃...", "source": "campus_wall" }
  ]
}
```

**响应**：
```json
{ "indexed": 1, "documentIds": ["a1b2..."] }
```

#### POST /query
知识问答（向量检索 + 图谱事实 enrichment + LLM 接地合成）。

**请求**（`QueryRequest`）：
```json
{ "question": "学校食堂有什么好吃的？", "conversationId": "可选", "topK": 5 }
```

**响应**：
```json
{
  "answer": "根据同学们的分享，学校食堂二楼的麻辣烫和三楼的面食比较受欢迎...",
  "sources": [ { "id": "a1b2...", "title": "食堂攻略", "snippet": "学校食堂二楼..." } ],
  "conversationId": "uuid"
}
```
> 无检索结果时 `answer` 固定为「暂无相关校园信息」。

#### POST /query/stream
流式知识问答，`Content-Type: text/event-stream`（SSE）。检索与 `/query` 相同，差别在逐 token 推送。

- 中间帧：`data: {"token": "片段"}`
- 末帧：`data: {"answer": "完整答案", "sources": [...], "conversationId": "uuid", "done": true}`
- 无命中：直接返回单帧 `{"answer": "暂无相关校园信息", "sources": [], "conversationId": "uuid", "done": true}`

#### POST /ingest-post
帖子知识入库：图片 VLM 读图 + 文字融合 + PII 脱敏 → 写 `Post/Item` 节点与向量。幂等（重发先删旧 Item）。

**请求**（`IngestPostRequest`）：
```json
{
  "post_id": 123,
  "intent": "second_hand",
  "category": "电子产品",
  "text": "九成新 iPad 出，联系我...",
  "images": [ { "object_name": "posts/123/1.jpg", "url": null } ],
  "tags": ["iPad", "平板"]
}
```
> `intent` 合法值：`lost_found | second_hand | part_time | team_up | daily`（默认 `daily`）。`images` 每项 `object_name`/`url` 二选一，缺 url 时用 `BACKEND_BASE_URL` 拼 `/api/v1/files/view`。

**响应**（`IngestPostResponse`）：
```json
{ "post_id": 123, "item_id": "post:123:item", "description": "脱敏后的融合描述", "indexed": true }
```

#### POST /match-posts
智能推荐：自然语言诉求 → 意图识别 + `campus_post_vector` 检索 + 意图过滤 + 逐条匹配理由。供 Java 后端还原成帖子卡片。

**请求**（`MatchPostsRequest`）：
```json
{ "question": "有人捡到一张蓝色校园卡吗", "intent": "可选", "topK": 5, "conversationId": "可选" }
```
> 未传 `intent` 由 LLM 自动识别；同意图两端互补（「丢了 X」匹配「捡到 X」）。

**响应**（`MatchPostsResponse`）：
```json
{
  "intent": "lost_found",
  "matches": [
    { "post_id": 88, "score": 0.91, "intent": "lost_found", "category": "证件",
      "description": "在图书馆捡到蓝色校园卡", "reason": "和你描述的蓝色校园卡高度吻合" }
  ],
  "prompt": "学长帮你找到 1 条可能匹配的帖子，是这个吗？",
  "conversationId": "uuid"
}
```

#### DELETE /posts/{post_id}
删帖 / 隐藏时同步删除图谱 `Post` 及其 `Item`，避免推荐到已删帖。响应 `{"deleted": true, "post_id": 123}`。

#### GET /documents
获取已索引文档列表。响应 `{"documents": [{"id", "title", "chunks", "createdAt"}]}`。

#### DELETE /documents/{doc_id}
删除文档及其 Chunk / 独占 Entity。命中 `{"deleted": true, "id": "..."}`，不存在返回 404。

## GraphRAG 工作原理

### 索引流程

```
原始文档
    │
    ▼
文档分块 (chunking)
    │
    ├──► 实体关系抽取 (LLM)
    │    "食堂" --位于--> "二楼"
    │    "麻辣烫" --属于--> "食堂"
    │
    ├──► 向量化 (Embedding)
    │    "学校食堂二楼麻辣烫很好吃"
    │    → [0.1, -0.3, 0.8, ...] (1024维)
    │
    ▼
写入 Neo4j
    ├── Document 节点
    ├── Chunk 节点（带向量索引）
    ├── Entity 节点
    └── 关系边
```

### 查询流程

```
用户问题
    │
    ▼
向量化 (Embedding)
    │
    ▼
向量检索 (Neo4j)
    找到最相似的 Chunk 节点
    │
    ▼
图遍历 (Neo4j)
    获取相关 Entity 和关系
    │
    ▼
构造 Prompt
    检索结果 + 历史对话 + 用户问题
    │
    ▼
生成回答 (Chat LLM)
    本地 qwen2.5:7b（失败降级 qwen-plus）
    │
    ▼
返回格式化回答
```

### 帖子入库与智能推荐流程（07/08）

```
发帖（图片 + 文字 + 板块 intent + 标签）
    │  POST /ingest-post
    ▼
逐图 VLM 读图 (describe_image)
    qwen2.5vl:7b → {description, category, color, brand, model, features}
    │
    ▼
文字 + 图片描述融合 → PII 脱敏 (sanitize.scrub_text)
    手机号/微信号/学号/身份证… → 中文方括号占位符
    │
    ├──► 向量化 (bge-m3, 1024 维)
    │
    ▼
写入 Neo4j 帖子子图
    (:Post)-[:DESCRIBES]->(:Item{embedding})
    (:Post)-[:HAS_INTENT]->(:Intent) / [:IN_CATEGORY]->(:Category) / [:TAGGED]->(:Tag)

用户自然语言诉求
    │  POST /match-posts
    ▼
意图识别 (detect_intent) → 向量化 → campus_post_vector 检索
    │  按 status=1 + 同 intent 过滤
    ▼
逐条生成一句话匹配理由 (chat LLM) → 返回帖子卡片数据
```

### 5. PII 脱敏模块 (sanitize.py)

`ingest_post` 入库**前**对「用户文字 + VLM 图片描述」统一脱敏，避免联系方式明文进入 Neo4j 图谱（隐私红线）。`scrub_text(text, name_blacklist=None)` 按正则把敏感信息替换为中文方括号占位符：

- `[手机号]` / `[身份证]` / `[银行卡]` / `[邮箱]` / `[QQ]` / `[微信号]` / `[学号]` / `[链接]` / `[宿舍]` / `[姓名]`
- `@提及`：真实提及 → `@某同学`（`@所有人/@全体成员` 等公告语义保留）

### 6. VLM 读图模块（describe_image）

帖子图片由 **VLM 角色**（`qwen2.5vl:7b`，失败降级 `qwen-vl-plus`）做物体识别与结构化标注：

- 图片来源：请求 `images[].url`，缺失时用 `BACKEND_BASE_URL` 拼 `/api/v1/files/view` 取 MinIO 对象。
- `VLM_IMAGE_MODE=base64`（默认）先下载图片转 base64 传给模型；`url` 模式直接传 URL。
- 输出 `{description, category, color, brand, model, features}`，融入 Item 节点属性，用于二手 / 失物等场景的精准推荐。

## LLM 链路：本地优先 + 云端降级

Chat 角色默认 **本地优先**（Ollama `qwen2.5:7b`）、失败时自动降级到云端 `qwen-plus`（`CHAT_FALLBACK_*`，默认开启），无需改代码即可切换：

1. 改走云端 / 内网模型，只动 `.env`：
```env
# 例：本地 demo（默认）——本地 qwen2.5:7b + 云端兜底
CHAT_BASE_URL=http://host.docker.internal:11434/v1
CHAT_MODEL=qwen2.5:7b
CHAT_API_KEY=ollama

# 例：容器部署——CHAT 直走内网 Qwen3.6-35B，云端降级关掉
# CHAT_BASE_URL=http://172.21.160.101:8003/v1
# CHAT_MODEL=Qwen3.6-35B
# CHAT_FALLBACK_ENABLED=false
```

2. 重启服务：
```bash
docker-compose up -d --build graphrag
```

> Embedding 不受影响（embed 降级默认关闭，向量须同模型同维度）；VLM 同理走 `VLM_*` / `VLM_FALLBACK_*` 独立配置。

## 常见问题

### Q: Neo4j 连接失败？

1. 检查 Neo4j 容器是否运行：`docker ps | grep neo4j`
2. 检查 Neo4j 端口：`localhost:7475` (HTTP) / `localhost:7688` (Bolt)
3. 检查密码是否正确

### Q: Ollama（embed / chat / vlm）失败？

1. 检查 Ollama 是否运行：`curl http://localhost:11434/api/tags`
2. 检查三套模型是否已拉取：`ollama list`（需有 `bge-m3` / `qwen2.5:7b` / `qwen2.5vl:7b`）
3. 容器内访问 Ollama 需要使用 `host.docker.internal:11434`
4. chat / vlm 本地失败会自动降级云端兜底（`*_FALLBACK_ENABLED`）；embed 降级默认关，本地不可用即直接报错

### Q: 向量维度不匹配？

确保 `EMBED_DIM` 与模型输出维度一致：
- bge-m3：1024 维
- 如更换模型，同步修改 `EMBED_DIM` 并重建向量索引

### Q: 回答质量不佳？

1. 检查知识图谱中是否有足够的数据
2. 调整向量检索的 `top_k` 值
3. 调整 Prompt 模板
4. 尝试更换 Chat LLM 模型
