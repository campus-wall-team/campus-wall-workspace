# campus-wall-monitor-ui 开发文档

> 最近更新：2026-06-15

## 项目简介

campus-wall-monitor-ui 是校园墙项目的管理员后台系统，面向运营和管理人员，提供 **RBAC 权限管理、运营数据看板、内容审核、举报/反馈/学生认证处理、用户/管理员/角色管理、知识库管理、操作审计、系统配置、Grafana 系统监控**等功能。基于 Vue 3 + Element Plus 开发，为桌面浏览器优化。

权限驱动是本后台的核心特征：后端是唯一鉴权权威，登录后由 `GET /api/v1/admin/auth/me` 下发权限码集合，前端据此过滤路由/菜单、隐藏按钮（仅 UI 隐藏，写接口仍由后端 `@RequirePermission` 兜底）。详见同目录的 [`管理端RBAC与运营看板设计方案.md`](./管理端RBAC与运营看板设计方案.md) 与 [`管理端实现落地记录.md`](./管理端实现落地记录.md)。

## 核心模块说明

### 1. 路由系统 (router/index.js)

每个业务路由都带 `meta.perms` 权限码，守卫据此放行：

```javascript
const routes = [
  {
    path: '/login',
    component: () => import('@/views/Login.vue'),
    meta: { public: true }                       // 公开页面，无需登录
  },
  {
    path: '/forbidden',
    component: () => import('@/views/Error403.vue'),
    meta: { hideMenu: true }                      // 403 页，不进菜单
  },
  {
    path: '/',
    component: MainLayout,
    children: [
      { path: 'dashboard',    component: () => import('@/views/Dashboard.vue'),        meta: { title: '运营看板', perms: ['stat:view'] } },
      { path: 'overview',     component: () => import('@/views/Overview.vue'),         meta: { title: '系统监控', perms: ['stat:view'] } },
      { path: 'moderation',   component: () => import('@/views/Moderation.vue'),       meta: { title: '内容审核', perms: ['moderation:queue'] } },
      { path: 'reports',      component: () => import('@/views/Report.vue'),           meta: { title: '举报处理', perms: ['report:list'] } },
      { path: 'feedbacks',    component: () => import('@/views/Feedback.vue'),         meta: { title: '意见反馈', perms: ['feedback:list'] } },
      { path: 'verification', component: () => import('@/views/Verification.vue'),     meta: { title: '学生认证', perms: ['verification:list'] } },
      { path: 'users',        component: () => import('@/views/UserMgmt.vue'),         meta: { title: '用户管理', perms: ['user:list'] } },
      { path: 'knowledge',    component: () => import('@/views/system/KnowledgeBase.vue'), meta: { title: '知识库管理', perms: ['knowledge:list'] } },
      { path: 'admins',       component: () => import('@/views/system/AdminUsers.vue'),meta: { title: '管理员',   perms: ['admin:list'] } },
      { path: 'roles',        component: () => import('@/views/system/Roles.vue'),     meta: { title: '角色权限', perms: ['role:list'] } },
      { path: 'configs',      component: () => import('@/views/SysConfig.vue'),        meta: { title: '系统配置', perms: ['sys:config'] } },
      { path: 'audit',        component: () => import('@/views/AuditLog.vue'),         meta: { title: '操作审计', perms: ['audit:view'] } }
    ]
  }
]
```

**导航守卫（router.beforeEach）**：
- 访问公开页面（`meta.public`）直接放行。
- 无 token 且访问非公开页面 → 重定向到登录页。
- 有 token 但 store 尚无权限（如刷新页面）→ 调 `useUserStore().fetchMe()` 拉 `GET /v1/admin/auth/me` 重建 roles/permissions。
- 目标路由 `meta.perms` 未被当前权限码满足（`!hasPerm`）→ 跳 `/forbidden`。

> 菜单不再手写 `el-menu-item`：`MainLayout.vue` 遍历静态路由，按 `hasPerm(meta.perms)` 过滤后自动渲染，新增页面只需在路由里加 `meta.perms`。

### 2. v-permission 按钮鉴权 (directives/permission.js)

页面内的写操作按钮挂 `v-permission` 指令，无对应权限码时直接从 DOM 移除：

```vue
<el-button v-permission="'moderation:reject'" type="danger" @click="onReject">驳回</el-button>
```

> `v-permission` 仅作 UI 隐藏。后端每个写接口都有独立 `@RequirePermission` 兜底，隐藏按钮不能被绕过调用。

### 3. HTTP 客户端 (api/http.js)

Axios 实例统一解包后端 `Result<T>` 信封、做业务错误提示与 401 处理：

```javascript
import { useUserStore } from '@/stores/user'
import { ElMessage } from 'element-plus'

const http = axios.create({
  baseURL: '/api',
  timeout: 30000
})

// 请求拦截器：自动添加管理端 Token
http.interceptors.request.use(config => {
  const token = localStorage.getItem(TOKEN_KEY)
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

// 响应拦截器：解包 Result<T> + 业务错误 + 401
http.interceptors.response.use(
  response => {
    const res = response.data
    if (res && typeof res.code !== 'undefined') {
      if (res.code === 200) return res.data            // 成功：直接返回 data
      ElMessage.error(res.message || '请求失败')        // 业务错误统一提示
      return Promise.reject(new Error(res.message))
    }
    return res
  },
  error => {
    if (error.response?.status === 401) {
      // Token 过期/无效：清 Pinia store + token，跳登录
      useUserStore().reset()
      localStorage.removeItem(TOKEN_KEY)
      router.push('/login')
    } else {
      ElMessage.error(error.response?.data?.message || error.message || '网络错误')
    }
    return Promise.reject(error)
  }
)
```

### 4. 状态管理 (stores/user.js)

Pinia `useUserStore` 是登录态与权限的唯一来源：

- state：`token` / `userInfo` / `roles`（如 `superadmin`/`moderator`/`viewer`）/ `permissions`（权限码集合）
- getter：`hasPerm(code)` —— 判定权限码是否命中（守卫、菜单、`v-permission` 共用）
- action：`login()`（调登录接口、存 token）、`fetchMe()`（拉 `/v1/admin/auth/me` 重建权限）、`logout()` / `reset()`（清空并登出）

> Pinia 已实际承载 `useUserStore`，不再是「已 `createPinia` 但闲置」的状态。`TOKEN_KEY = 'campus_monitor_token'`，token 来源唯一化（不再在 http.js/router/Login/MainLayout 四处散读）。

### 5. API 接口 (api/index.js)

集中定义全量管理端接口，主要分组：

| 分组 | 接口 |
|------|------|
| 认证 | `POST /v1/admin/login`、`GET /v1/admin/auth/me`、`POST /v1/admin/auth/logout` |
| 瞬时卡片 | `GET /v1/admin/stats`（注意：无 `/overview` 后缀，瞬时总览卡片用此接口） |
| 运营看板 | `GET /v1/admin/stat/overview`、`/stat/trend`、`/stat/active`、`/stat/distribution`、`/stat/top-posts` |
| 内容审核 | `GET /v1/admin/moderation/queue`、`POST /moderation/scan`、`/moderation/{id}/approve`、`/moderation/{id}/reject` |
| 举报处理 | `GET /v1/admin/reports`、处理/忽略 |
| 反馈处理 | `GET /v1/admin/feedbacks`、回复 |
| 学生认证 | `GET /v1/admin/verification`、审核通过/驳回 |
| 用户管理 | `GET /v1/admin/users`、封禁/解封 |
| 知识库 | `GET /v1/admin/knowledge/docs`、`POST /knowledge/import`（multipart，可选脱敏）、`DELETE /knowledge/docs/{id}` |
| 管理员 | `GET/POST/PUT /v1/admin/admins`、重置密码、踢人 |
| 角色权限 | `GET /v1/admin/roles`、`/roles/{id}/permissions` 分配 |
| 操作审计 | `GET /v1/admin/audit` |
| 系统配置 | `GET /v1/admin/configs`、`PUT /v1/admin/configs` |

> 易混点：瞬时卡片接口是 `/v1/admin/stats`（**无 `/overview`**，与 `AdminModerationController` 的 `GET /admin/stats` 同源）；运营看板才用 `/v1/admin/stat/overview` 等 `stat/*` 系列。两套并存、口径分工不同。

### 6. 登录页 (views/Login.vue)

- 管理员账号密码登录，调 `useUserStore().login()`。
- 登录成功后 `fetchMe()` 拿 roles/permissions，token 存 localStorage。
- 跳转到运营看板（dashboard）。

### 7. 运营看板 (views/Dashboard.vue)

业务运营专用看板，数据来自后端 `stat/*` 系列接口：

- **KPI 卡**：总用户 / DAU / 今日新增（含环比）/ 总帖 / 今日新增帖 / 总评论 / AI 提问总数 / 待审积压。
- **趋势折线**：7 / 30 / 90 天，支持新增用户、新增帖、评论、AI 问答、待审积压等多指标。
- **分布饼图**：板块（category）/ 校区（campus）/ 反馈类型（feedbackType）/ 审核状态（moderationStatus）。
- **热帖 Top10**：横向条形 / 列表。

所有图表统一用 `components/BaseChart.vue`（`vue-echarts`，开 `autoresize`，组件卸载时清理实例防内存泄漏），各处只传 `option`。

### 8. 系统监控 (views/Overview.vue)

- **关键指标卡片**：帖子数、用户数、待审核数等（瞬时，对接 `GET /v1/admin/stats`）。
- **Grafana iframe 嵌入**：整页 kiosk 内嵌业务/主机/JVM 三块看板，实时展示系统与中间件监控。
- 服务存活灯展示中间件健康（已移除 Chroma，向量检索统一由 Neo4j 原生向量索引承载）。

### 9. 内容审核页 (views/Moderation.vue)

- **待审核列表**：展示 AI 标记的待审核内容。
- **审核操作**：通过（内容正常发布）/ 驳回（不通过，可填写原因）；按钮挂 `v-permission`。
- 对接后端 `/v1/admin/moderation/*`。

### 10. 知识库管理页 (views/system/KnowledgeBase.vue)

- **文档列表**：展示已导入知识库的文档（文档ID/标题/摘要/导入时间），对接 `GET /v1/admin/knowledge/docs`。
- **导入文档**：上传文件（`.txt/.md/.csv/.html/.htm/.pdf/.docx`）或粘贴文本两种入口，可勾选「脱敏导入」；对接 `POST /v1/admin/knowledge/import`（multipart）。服务端切割/向量化由 campus-wall-ai 的 `/ingest` 承载。
- **删除文档**：`DELETE /v1/admin/knowledge/docs/{id}`。
- 写操作按钮挂 `v-permission`（`knowledge:import` / `knowledge:delete`），进入页面需 `knowledge:list`。

### 11. 其余管理页

举报处理、意见反馈、学生认证、用户管理、管理员、角色权限、操作审计、系统配置各页结构相近：权限驱动进入、列表 + 写操作按钮挂 `v-permission`、对接对应 `api/index.js` 接口。

## 常见问题

### Q: Grafana iframe 无法加载？

1. 检查 Grafana 是否允许嵌入：`GF_SECURITY_ALLOW_EMBEDDING=true`。
2. 检查是否配置了匿名访问：`GF_AUTH_ANONYMOUS_ENABLED=true`。
3. 检查 `config.js` 中的 Grafana 看板 UID 是否为真实值（`campus-business` / `host-system` / `jvm-app`，整页 kiosk）。
4. 开发态确认 `/grafana` 代理目标指向 A 机 `172.21.160.212:3000`。

### Q: 登录后跳转失败 / 进页面被踢到 /forbidden？

1. 检查 Token 是否正确保存（`TOKEN_KEY='campus_monitor_token'`）。
2. 检查 `fetchMe()` 是否成功拉到 roles/permissions（`GET /v1/admin/auth/me`）。
3. 检查目标路由 `meta.perms` 是否在当前账号权限码集合内（后端 RBAC 种子是否授予对应角色）。
