## 2. 权限码 → 角色矩阵（25 个权限码）

| 模块 | 权限码 | superadmin | moderator | viewer |
|------|--------|:--:|:--:|:--:|
| 看板 | `stat:view` | ✓ | ✓ | ✓ |
| 审核 | `moderation:queue`(menu) / `scan` / `approve` / `reject` | ✓ | ✓ | 仅 queue |
| 举报 | `report:list` / `handle` / `ignore` | ✓ | ✓ | 仅 list |
| 反馈 | `feedback:list` / `reply` | ✓ | ✓ | 仅 list |
| 认证 | `verification:list` / `review` | ✓ | ✓ | 仅 list |
| 用户 | `user:list` / `ban` / `unban` | ✓ | ✓ | 仅 list |
| 管理员 | `admin:list` / `create` / `update` / `reset-pwd` / `kick` | ✓ | ✗ | 仅 list(menu) |
| 角色 | `role:list` / `assign` | ✓ | ✗ | 仅 list(menu) |
| 审计 | `audit:view` | ✓ | ✗ | ✓(menu) |
| 配置 | `sys:config` / `sys:config-save` | ✓ | ✗ | 仅 sys:config 只读 |

> viewer = 所有 `menu` 类权限（只读浏览各页）；moderator = viewer + 审核/举报/反馈/认证/封禁的写权限；superadmin = 全部。

## 5. 关键技术落点（与设计稿一致）

- **鉴权**：自定义 `@RequirePermission` + `AdminAuthInterceptor`（非 Spring Security / Sa-Token）；管理端**独立密钥 `ADMIN_JWT_SECRET` + token claim `type=admin`**，与 C 端物理隔离。
- **看板时序**：`stat_daily` 快照 + SQL 直查；**DAU = Redis HyperLogLog**（`dau:yyyyMMdd`，C 端 JwtInterceptor 打点，40 天 TTL），WAU/MAU 用 PFCOUNT 合并多日 HLL。
- **审计**：`@OperationLog` + AOP，仅记写操作 + 关键 ID，`@Async` 落库。

## 7. 已知/有意延后（非 bug）

- **数据权限 SCHOOL 未在查询层强制**：`data_scope` 已解析进 `RequestContext`，但 list/stat 查询暂未按 SCHOOL 加 `university_id` 过滤。当前 3 个种子角色均为 `ALL`，无实际越权；若启用 SCHOOL 角色需在各 list Service 补过滤。
- **`sys_config` 消费侧未接入**：表/CRUD/`SysConfigService.getInt/getBoolean` 已就绪，但 AI 阈值、限流等参数仍读硬编码/yaml，未改为读 `sys_config`（先建仓，消费侧逐步接入）。
- **V4.2 的 ALTER 非幂等**：与既有 V3.8 同模式，Flyway 单次执行已 gate；部分应用/手改 schema 的恢复场景需注意。
- **前端构建**：需 Node 18+（Vite 5）；本机 Node 11 未能验证构建。
- **P4「消灭字段兼容垫片」未落地**：`Moderation.vue` 仍保留 `r.aiScore ?? r.ai_score` 兜底（camelCase/snake_case 双读）。属遗留技术债（非 bug），后端 `Result.data` 已统一 camelCase 后可去除。
- **config.js / Overview.vue 残留旧文案**：`config.js` 顶部注释与 `Overview.vue` 的 `el-alert` 仍残留「占位 `campus-overview` / `panelId` 替换」旧文案，与已落地的真实 UID（`campus-business`/`host-system`/`jvm-app` 整页 kiosk）自相矛盾，待清理。
