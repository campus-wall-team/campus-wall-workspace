```text
┌─────────────────────────────────────────────────────────────┐
│                        前端 (uni-app)                        │
│  热帖页  │  搜索页  │  AI偏好页  │  学生认证页  │  管理端   │
└─────────┴─────────┴───────────┴─────────────┴──────────┘
                              │
┌─────────────────────────────────────────────────────────────┐
│                       后端 (Spring Boot)                     │
│  PostRankController  SearchController  AgentController       │
│      │                     │                  │             │
│  PostRankService     SearchHotService    AgentService        │
│      │                     │                  │             │
│  Redis ZSet + DB     Redis ZSet + DB   AI Preference Prompt  │
│      │                     │                                │
│  Scheduled Task      Scheduled Task                          │
│  (热度聚合/过期清理)  (窗口滑动/过期清理)                      │
└─────────────────────────────────────────────────────────────┘
```

> 注：上图为概念示意。实际类名为 `RankController`（热帖榜 `/ranks/posts` + 热搜榜 `/ranks/search-hot`）、`PostRankService`/`SearchHotRankService`、`RankRefreshTask`。`AgentController` 已不在进程内做 AI 推理，而是把 `/ai-senior/agent` 转发到 Python LangGraph agent（campus-wall-ai，:8011）由其注入偏好；`AgentService`（进程内 Planner-Executor-Synthesizer + 偏好注入）仅作 `remote-enabled=false` 时的兜底。

核心设计原则：
1. **读多写少**：榜单读走 Redis ZSet，写只更新计数或分数，异步任务定期聚合。
2. **时间窗口**：热帖、热搜均使用 Redis 过期 + 滑动窗口，到点自动失效。
3. **最小入侵**：复用现有 `PostVO`、`Result`、`RequestContext`、`MinioUtil` 等基础设施。
4. **认证安全**：证件图片使用 MinIO 私有路径 + 后端代理访问，OCR 结果仅用于初筛，关键决策由人工复核。

## 3. AI 偏好设置生效（修复现有链路）

> 截至 2026-06 已落地。AI 对话推理在 v2 起已迁移到独立的 **Python LangGraph agent（campus-wall-ai，:8011）**，由它主导偏好注入；Java 侧仅在 `ai.agent.remote-enabled=false` 时作为进程内兜底链路，同样已接好偏好。

### 3.1 现状（已实现）

- `AiPreferenceController` 提供 `GET /api/v1/ai-preference/get`、`POST /api/v1/ai-preference/save`、`GET /api/v1/ai-preference/system-prompt`。
- **Python 主链**（`campus-wall-ai/app/agent/service.py`）在 `_prepare_state` 中经 `preference_dao.get_preference(user_id)` + `preference.build_system_prompt(...)` 注入 `preference_prompt`；`nodes.build_synthesis_prompts` 把人设/`custom_prompt` 放到接地硬性规则**之下**（注入护栏，防止用户在 `custom_prompt` 里写“忽略限制”压制反幻觉约束）。

## 4. 热帖榜（日榜 / 周榜 / 月榜）

### 4.1 算法设计：综合热度分 + 滑动窗口

热度分公式（参考 Hacker News / 微博热搜）：

```
score = (viewWeight * viewCount + likeWeight * likeCount
         + commentWeight * commentCount + collectWeight * collectCount)
        / pow(hoursSincePublish + 2, gravity)
```

建议参数（可配置到 `application.yaml`）：
- `viewWeight = 1`
- `likeWeight = 5`
- `commentWeight = 8`
- `collectWeight = 3`
- `gravity = 1.5`

榜单按 score 倒排。帖子发布时间超过窗口期后自然无法入榜。

### 4.2 数据流

1. **实时写**：用户浏览帖子时，`PostPublishService.incrementViewCount()` 同时给 Redis 计数器 `campus:post:views:{postId}` +1。
2. **定时聚合**：每 5 分钟执行一次 `HotPostRankTask`，计算窗口内帖子 score，写入三个 ZSet：
   - `campus:rank:post:daily`（24h）
   - `campus:rank:post:weekly`（7d）
   - `campus:rank:post:monthly`（30d）
3. **自动过期**：写入时设置 TTL = 窗口期，或任务中用 `ZREMRANGEBYSCORE` 移除过期帖子。
4. **读榜单**：Controller 直接 `ZREVRANGE` 取前 N。

## 5. 热搜榜

### 5.1 算法设计：滑动窗口 + 搜索次数 + 标签

与现有 `search_record` 表互补：
- **持久化**：仍用 `search_record` 记录总搜索次数（用于长期分析）。
- **实时榜**：用 Redis 滑动窗口 ZSet，按窗口内搜索次数倒排。

实现方式：
1. 每次搜索时给当前时间窗口的 ZSet 加 1 分：
   - `campus:search:hot:{date}`，按天分桶（如 `campus:search:hot:20260613`）。
   - 每个分桶 TTL = 30 天，自动过期。
2. 读取榜单时，按周期合并最近 N 个分桶：
   - 24h：合并今天 + 昨天（按小时比例折算）。
   - 7d：合并最近 7 天。
   - 30d：合并最近 30 天。
3. 合并后计算“热/新/爆”标签：
   - 新：首次进入前 50。
   - 热：搜索次数 > 100。
   - 爆：搜索次数 > 1000 或环比增速 > 300%。

### 5.2 Redis Key 规范

```java
// 按天分桶的热搜 ZSet：member=keyword, score=当天搜索次数
campus:search:hot:yyyyMMdd

// 合并后的榜单缓存（读多写少）
campus:search:rank:day
campus:search:rank:week
campus:search:rank:month

// 昨日榜单缓存（用于环比）
campus:search:rank:yesterday
```

## 6. 学生认证（AI 初筛 + 人工复核）

### 6.1 流程

```
用户上传正面 -> 上传反面 -> 提交认证 -> AI OCR 识别 ->
  ├─ 高置信度通过 -> 待人工复核（异步）-> 管理员通过/驳回
  └─ 低置信度/异常 -> 直接待人工复核
```

状态机：
- `pending` 待提交（用户未提交）
- `submitted` 已提交，等待 AI 初筛
- `ai_passed` AI 初筛通过，等待人工复核
- `ai_failed` AI 初筛失败（自动转人工复核）
- `manual_passed` 人工复核通过（认证成功）
- `manual_rejected` 人工复核驳回

### 6.2 数据库表

```sql
CREATE TABLE IF NOT EXISTS student_verification (
    id                  bigint auto_increment primary key comment '主键ID',
    user_id             bigint          not null comment '用户ID',
    real_name           varchar(50)     null comment '真实姓名（OCR识别）',
    student_no          varchar(50)     null comment '学号（OCR识别）',
    university_name     varchar(100)    null comment '学校名称（OCR识别）',
    college             varchar(100)    null comment '学院（OCR识别）',
    front_object_name   varchar(500)    not null comment '学生证正面 MinIO 对象名',
    back_object_name    varchar(500)    not null comment '学生证反面 MinIO 对象名',
    status              varchar(32)     default 'pending' not null comment '认证状态',
    ai_score            int             null comment 'AI 置信度 0-100',
    ai_reason           varchar(512)    null comment 'AI 初筛说明',
```

### 6.5 AI OCR 初筛

**实现方式**：
- 优先调用本地 / 内网 OCR 服务（如 PaddleOCR / 自己部署的 LLM）。
- 若无本地 OCR，可调用云端 OCR（阿里云、腾讯云等）。
- OCR 结果要求识别出：姓名、学号、学校名。
- 将识别结果与 `user.university_id` 关联的学校名做模糊匹配，给出置信度。

**初筛逻辑**：
- 置信度 >= 80 且学校名匹配：状态 `ai_passed`。
- 置信度 < 80 或学校名不匹配：状态 `ai_failed`（仍进入人工复核）。
- 关键字段缺失：状态 `ai_failed`。
