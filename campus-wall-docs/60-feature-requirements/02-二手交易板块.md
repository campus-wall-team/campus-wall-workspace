# 02 · 二手交易板块

> 依赖 [`01-板块分类体系-基础架构.md`](./01-板块分类体系-基础架构.md)。本篇只描述二手交易板块相对底座的**差异化**:价格(必填)、联系方式(可选)、展示与一键复制。`price`/`contact` 字段已在 `01` 的 `V3.3__post_board_fields.sql` 建好。

> ✅ **已实现(2026-06-10)**:发布页价格输入 + **「面议」开关**(`PostDTO.negotiable`,勾选时 `price` 存 NULL 跳过校验);后端 `PostPublishService` 服务端独立校验;主页卡片与详情页展示价格/联系方式并可一键复制(复用 `uni.setClipboardData`)。**「已售出」状态**已实现:`V3.3` 新增 `post.is_sold`,前端置灰展示。

## 一、概述

### 目标
二手交易板块(`code=secondhand`)用于存放用户的闲置交易帖。与普通帖的差异:

1. **发布时**必须在帖子发布页选择"二手交易类",并**输入价格(必填)**才能发布;联系方式可选。
2. **浏览时**价格醒目展示;联系方式直接展示在**主页帖子卡片**和**帖子详情页**,用户可**一键复制**。

### 对应需求原文
> 二手交易类用于存放用户的二手交易,在此父类当中发布需要在帖子发布页就要选择二手交易类,选择以后会在该页当中提醒用户输入价格,联系方式(可选)等信息,其中联系方式要直接展示在主页的帖子信息和帖子详情页等页当中,用户可以直接复制帖子当中联系方式信息。

## 二、现状与可复用资产

| 资产 | 位置 | 复用点 |
|------|------|--------|
| 扩展字段 `price`/`contact` | `post` 表(`01` 已建) | 直接读写 |
| 板块校验枚举 `BoardType.SECONDHAND`(`requirePrice=true`) | `community/enums/BoardType.java`(`01` 已建) | 后端必填校验 |
| 一键复制 | `pages/post/detail.vue` 现有 `uni.setClipboardData` | 直接复用到卡片与详情 |
| 发布提交链路 | `publish.vue` `submitPost` → `PostPublishService.publishPost` | 透传新字段 |
| 异常→提示链路 | `BusinessException` → 全局异常 → `Result.error` → 前端 toast | 校验失败提示 |

## 三、技术方案(如何实现)

### 3.1 发布页:价格必填 + 联系方式可选

在 `publish.vue` 板块字段区(`boardCode === 'secondhand'` 时显示):

```vue
<!-- 二手交易专属字段 -->
<view v-if="selectedBoardCode === 'secondhand'" class="board-fields">
  <view class="field-row">
    <text class="field-label">价格 <text class="required">*</text></text>
    <input v-model="form.price" type="digit" placeholder="请输入出售价格(元)" />
  </view>
  <view class="field-row">
    <text class="field-label">联系方式</text>
    <input v-model="form.contact" placeholder="微信/手机号(选填,将展示在帖子上)" />
  </view>
</view>
```

前端提交前校验(`submitPost` 内):

```js
if (selectedBoardCode.value === 'secondhand') {
  if (!form.price || Number(form.price) <= 0) {
    uni.showToast({ title: '二手交易帖请填写价格', icon: 'none' })
    return
  }
}
// postData 增加:price、contact
```

### 3.2 后端:服务端独立校验(不信任客户端)

在 `PostPublishService.publishPost(PostDTO dto, Long userId)` 入口:

```java
BoardType board = BoardType.fromCategory(dto.getCategory());
if (board.isRequirePrice() && (dto.getPrice() == null
        || dto.getPrice().compareTo(BigDecimal.ZERO) <= 0)) {
    throw new BusinessException("二手交易帖必须填写有效价格");
}
// 落库:post.setPrice(dto.getPrice()); post.setContact(dto.getContact());
```

`BusinessException` 由全局异常处理转 `Result.error`,前端弹 toast。

### 3.3 展示 + 一键复制

**主页卡片**(`index.vue`,`post.boardCode === 'secondhand'` 分支):价格高亮 + 联系方式行(有才显示)。

```vue
<view v-if="post.boardCode === 'secondhand'" class="sh-info">
  <text class="sh-price">¥{{ post.price }}</text>
  <view v-if="post.contact" class="sh-contact" @tap.stop="copyContact(post.contact)">
    <text>联系:{{ post.contact }}</text>
    <text class="copy-btn">复制</text>
  </view>
</view>
```

**复制方法**(复用 `detail.vue` 现有写法,卡片与详情共用):

```js
const copyContact = (text) => {
  uni.setClipboardData({
    data: text,
    success: () => uni.showToast({ title: '联系方式已复制', icon: 'success' })
  })
}
```

> `@tap.stop` 阻止冒泡到卡片跳转;复制按钮在卡片和详情页正文区各放一处。

**详情页**(`detail.vue`):正文卡片增加"价格 + 联系方式 + 复制"行,`post.value` 映射处补 `price`/`contact`/`boardCode`。

## 四、数据模型 / 接口

- 字段:`post.price`(`decimal(10,2)`)、`post.contact`(`varchar(100)`)——`01/V3.3` 已建。
- `PostDTO` 增 `price`(BigDecimal)、`contact`(String);`PostVO` 同名字段经 `BeanUtils` 自动带出。
- 接口:`POST /api/v1/posts/publish` 请求体含 `price`/`contact`;列表/详情响应含 `price`/`contact`/`boardCode`。

## 六、实现步骤

1. 确认 `01` 的 `V3.3` 已落库、`PostDTO/PostVO` 已含字段。
2. 后端:`PostPublishService` 加二手校验与落库。
3. 前端发布页:二手字段区 + 校验 + 提交。
4. 前端展示:卡片与详情的价格/联系方式/复制。
5. 联调:无价格被拒(toast)、有价格成功;卡片与详情正确显示并可复制。

## 七、验收标准

- [ ] 发布页选"二手交易",出现价格(必填，可为0)、联系方式(选填)输入框。
- [ ] 不填价格点发布 → 前端拦截提示;绕过前端直接调接口 → 后端返回错误。
- [ ] 发布成功后,主页该帖卡片显示价格;填了联系方式则显示并可点"复制",复制后 toast 提示。
- [ ] 帖子详情页同样显示价格、联系方式并可复制。

## 八、风险与待确认项

1. **联系方式与隐私**:联系方式明文展示在公开列表,需在发布页提示用户"将公开展示";AI 知识入库链路对联系方式做脱敏不入图谱明文(见 [`07`](./07-AI知识入库-Neo4j图谱.md))。

2. **价格类型**:`price` 用 `decimal`,前端 `type="digit"` 限数字;是否需要"面议"选项?若需要,可加一个"面议"开关,勾选时 `price` 存 NULL 并跳过必填校验(待产品确认)。
   需要"面议"选项，加一个"面议"开关，勾选时 `price` 存 NULL 并跳过必填校验
3. **交易状态**:是否需要"已售出"状态(置灰/下架)?本期未含,可作为后续迭代。
   需要"已售出"状态(置灰/下架)
