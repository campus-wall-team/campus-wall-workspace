# 08 · AI 智能推荐与问答

> AI 三篇之三(**应用层**),闭环。本篇解决"用户用自然语言提问 → AI 检索 [`07`](./07-AI知识入库-Neo4j图谱.md) 入库的帖子 → 把匹配帖子推送给用户、询问'是不是这个'"。这是 AI 作为项目亮点的最终用户价值:**减少手动刷帖,直接问出想要的帖子**。

## 一、概述

### 目标
用户在 AI 页用自然语言提问,AI 识别意图、检索匹配,把对应帖子以卡片形式推送并询问确认:

| 用户提问(场景) | 匹配的发帖 | AI 行为 |
|------|------|------|
| "有没有人捡到一个蓝色的书包"(丢东西) | 别人发的"捡到蓝色书包" | 推送该帖,问"是这个吗?" |
| "有没有人出售单车 / 求购《大学物理》" | 别人发的"出售单车/《大学物理》" | 推送该帖,问"是否购买?" |
| 兼职 / 组队同理 | 对应板块帖子 | 推送匹配帖 |

### 对应需求原文(摘要)
> 等到用户b……来询问ai,有没有人捡到一个蓝色的书包,ai会将用户a的帖子推给用户b,然后询问是否是这个……(出售场景)询问他是否要购买……让大家都可以通过ai去减少手动刷帖子的时间。

### 关键洞察:发帖端与求问端同 intent 互补
"捡到 X"(发帖,`intent=lost_found`)与"丢了 X"(求问,`intent=lost_found`)是**同一意图的两端**,语义天然互补,向量检索可匹配。二手"出售"与"求购"同归 `second_hand`。因此**按同一 intent 过滤即可**,无需拆分。

## 三、技术方案(如何实现)

### 3.1 接口决策:新增 `POST /match-posts`(与 `/query` 并列)

`/query` 是"基于知识图谱答校园问题"(返回 answer 文本);`/match-posts` 是"把诉求匹配到具体帖子"(返回帖子列表)。意图与返回结构不同,**分开**。

### 3.2 检索流程(`graph_store.match_posts` 新增)

```python
VALID_INTENTS = {"lost_found", "second_hand", "part_time", "team_up", "daily"}
_INTENT_SYS = (
    "判断用户问题属于哪种校园诉求,只输出一个英文标签:"
    "lost_found(找失物/捡到/寻物)、second_hand(买卖二手,含求购与出售)、"
    "part_time(兼职/招聘)、team_up(组队/找队友)、daily(其他)。只输出标签本身。"
)

def detect_intent(question: str) -> Optional[str]:
    try:
        out = llm.chat(_INTENT_SYS, question, temperature=0.0).strip().lower()
        return out if out in VALID_INTENTS else None
    except Exception:
        return None

_REASON_SYS = "你是校园助手。用一句话说明这条帖子为何匹配用户诉求,不超过30字,中文。"

def match_posts(self, question: str, intent: Optional[str], top_k: int = 5) -> dict:
    intent = intent or self_detect(question)        # 未传则自动识别
    q_emb = llm.embed_one(question)
    with self._driver.session() as s:
        rows = s.run(
            f"CALL db.index.vector.queryNodes('{settings.POST_VECTOR_INDEX_NAME}', $k, $emb) "
            "YIELD node, score "
            "MATCH (p:Post)-[:DESCRIBES]->(node) "
            "WHERE p.status = 1 AND ($intent IS NULL OR p.intent = $intent) "
            "RETURN p.postId AS post_id, score, p.intent AS intent, "
            "       p.category AS category, node.description AS description "
            "ORDER BY score DESC LIMIT $topK",
            k=top_k * 3, emb=q_emb, intent=intent, topK=top_k,
        )
        matches = [dict(r) for r in rows]
    # 逐条生成匹配理由(可优化为一次批量调用以省 token)
    for m in matches:
        m["reason"] = llm.chat(_REASON_SYS,
            f"用户诉求:{question}\n帖子物品:{m['description']}", temperature=0.3).strip()
    return {"intent": intent, "matches": matches}
```

> 先取 `top_k*3` 候选再按 intent 过滤,避免过滤后不足 top_k。
>
> `detect_intent`/`reason` 用的 `llm.chat` 与 `llm.embed_one` 均已是**本地优先 + 云端降级**(见 graphrag `llm.py`):本地 Ollama 不可用时自动降级云端,问答链路不中断。⚠️ 但 `embed_one` 降级须同模型同维度,否则与 `07` 入库向量空间不兼容(详见 [`09`](./09-本地大模型部署与降级.md))。

### 3.3 Pydantic 模型 + 端点(`main.py` 新增)

```python
class MatchPostsRequest(BaseModel):
    question: str
    intent: Optional[str] = None
    topK: int = 5
    conversationId: Optional[str] = None

class MatchedPost(BaseModel):
    post_id: int
    score: float
    intent: Optional[str] = None
    category: Optional[str] = None
    description: str = ""
    reason: str = ""

class MatchPostsResponse(BaseModel):
    intent: Optional[str] = None
    matches: List[MatchedPost] = []
    prompt: str = ""              # 给前端的话术
    conversationId: str

@app.post("/match-posts", response_model=MatchPostsResponse)
def match_posts(req: MatchPostsRequest):
    conv_id = req.conversationId or str(uuid.uuid4())
    res = store.match_posts(req.question, req.intent, max(1, req.topK))
    n = len(res["matches"])
    prompt = (f"学长帮你找到 {n} 条可能匹配的帖子,是这个吗?" if n
              else "暂时没有找到匹配的帖子,要不要换个说法再问问?")
    return MatchPostsResponse(intent=res["intent"], matches=res["matches"],
                              prompt=prompt, conversationId=conv_id)
```

### 3.4 Java 集成:还原成帖子卡片

新增 `POST /api/v1/ai-senior/match-posts`(并入 `AiSeniorController` 或新建 `PostMatchController`):

```java
@PostMapping("/match-posts")
public Result<Map<String,Object>> matchPosts(@RequestBody PostMatchDTO dto,
                                             @RequestAttribute("userId") Long userId) {
    Map<String,Object> rag = ragBackend.matchPosts(dto.getQuestion(), dto.getIntent(), dto.getTopK());
    List<Map<String,Object>> raw = (List<Map<String,Object>>) rag.get("matches");
    List<Map<String,Object>> cards = new ArrayList<>();
    for (Map<String,Object> m : raw) {
        Long pid = ((Number) m.get("post_id")).longValue();
        PostVO vo = postService.getPostDetail(pid, userId);   // 复用现有
        if (vo == null) continue;                              // 跳过已删/隐藏
        Map<String,Object> card = new HashMap<>();
        card.put("post", vo);
        card.put("matchScore", m.get("score"));
        card.put("matchReason", m.get("reason"));
        cards.add(card);
    }
    Map<String,Object> data = new HashMap<>();
    data.put("intent", rag.get("intent"));
    data.put("prompt", rag.get("prompt"));
    data.put("posts", cards);
    return Result.success(data);
}
```

`GraphRagBackend.matchPosts`(复用 `postForMap`):

```java
public Map<String,Object> matchPosts(String question, String intent, Integer topK) {
    Map<String,Object> body = new HashMap<>();
    body.put("question", question);
    if (intent != null) body.put("intent", intent);
    body.put("topK", topK == null ? 5 : topK);
    return postForMap("/match-posts", body);
}
```

## 六、实现步骤

1. graphrag:`match_posts`/`detect_intent` + `/match-posts` 端点;先用 `07` 灌几条数据,`curl` 验证检索。
2. Java:`GraphRagBackend.matchPosts` + Controller(组卡片,过滤已删帖)。
3. 前端:`aiApi.matchPosts` + `chat.vue` 卡片渲染 + 跳转。
4. 端到端:发"捡到蓝书包"帖 → 另一用户问"有没有人捡到蓝色书包" → 收到该帖卡片 + "是这个吗?"。

## 七、验收标准

- [ ] 提问"有没有人捡到蓝色书包",返回此前发布的"捡到蓝书包"帖卡片,带匹配理由。
- [ ] 提问"求购《大学物理》",返回"出售《大学物理》"帖。
- [ ] 意图过滤生效:问二手不会串出兼职/组队帖。
- [ ] 无匹配时返回友好话术,不报错。
- [ ] 卡片可点击跳转帖子详情;在详情页可走站内私信联系。
- [ ] 已删除/隐藏帖不出现在推荐结果中。

## 八、风险与待确认项

1. **意图识别准确率**:`detect_intent` 用 LLM 单分类,边界问题(如"有人卖书也招兼职")可能误判;可让前端在 AI 页提供意图快捷选项辅助传 `intent`。
2. **冷启动**:图谱为空时无可推荐;需先通过 `07` 实时入库 + [`14-data-pipeline`](../14-data-pipeline/) 批量回灌存量帖子。
3. **reason 成本**:逐条调 LLM 生成理由有 token 成本与延迟,建议合并为一次批量调用,或先返回卡片、理由懒加载。
4. **联系方式获取**:AI 只负责"把帖子推给你",联系发帖人统一回到帖子详情页走站内私信/复制联系方式(见 `02`),AI 链路不传递明文联系方式(隐私,见 `07`)。
5. **时效**:失物/二手有时效,建议检索排除过旧或已成交帖(可加时间衰减或 `status` 过滤)。
