## 一、概述

### 目标
引入一个**轻量化视觉大模型(VLM)**,对帖子图片做特征标注,生成结构化物品描述。需求中的四个场景在"读图"层面归纳为两类:

| 场景 | 图 | 文 | VLM 职责 |
|------|----|----|---------|
| 场景 1 / 3(有图有文) | ✓ | ✓ | **图文参照**:在用户文字基础上,识别图片中物品的**额外特征**(颜色、品牌、型号、磨损等),与用户描述融合 |
| 场景 2 / 4(有图无文) | ✓ | ✗ | **纯图描述**:对图片独立描述(如"蓝色双肩书包,侧袋有水壶位""《大学物理》教材,第X版") |

> 兼职、组队板块同理:VLM 对图片/海报做结构化理解,产出可检索的描述。

### 对应需求原文(摘要)
> 我需要一个轻量化的大模型将图片的东西进行标注转化存入……(场景 1)将描述的文字和图片做参照,看看图片中的蓝色书包还有什么其他的特征……(场景 2)只发布了一张图片……可以读取图片的轻量化大模型应该对这个图片进行描述后存入……(场景 4)描述成这是一本《大学物理》的书,是什么版本的……

## 三、技术方案(如何实现)

### 3.1 VLM 选型(本地优先 + 云端降级)

做成与 chat/embed 同构的**独立可配置客户端**,采用**本地优先 + 云端降级 (failover)**:主用本地视觉模型,本地不可用时自动降级到云端视觉模型,与 graphrag chat/embed 同一套降级机制:

| 角色 | 配置 | 说明 |
|------|------|------|
| **本地 Ollama qwen2.5vl:7b(主,推荐)** | `VLM_BASE_URL=http://host.docker.internal:11434/v1`、`VLM_MODEL=qwen2.5vl:7b` | 数据不出本地(失物/二手图片含隐私),GB10 本地算力,与现有 bge-m3 同生态 |
| 云端 DashScope qwen-vl-plus(降级兜底) | `VLM_FALLBACK_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1`、`VLM_FALLBACK_API_KEY=<key>`、`VLM_FALLBACK_MODEL=qwen-vl-plus` | 仅本地失败时调用;图片需公网可达或转 base64,数据上云 |

> Ollama 模型 tag 以实际 `ollama pull` 为准(如 `qwen2.5vl:7b` / `minicpm-v` / `llava`);中文物品识别优先 qwen 系列。资源紧张可换更轻的 `minicpm-v`。

### 3.2 取图方式:`url` vs `base64`(关键网络细节)

VLM 通过 OpenAI 兼容的 vision messages 接收图片,有两种模式,**因部署拓扑不同而异**:

```
graphrag(容器) ──调用── VLM
图片源:MinIO → Java 公开端点 GET /api/v1/files/view?objectName=...
```

- **`base64` 模式(本地 Ollama 推荐,默认)**:graphrag 容器自己经 `host.docker.internal:8080/api/v1/files/view` **拉取图片字节并转 base64**,内嵌进 message。不依赖 Ollama(宿主机进程)能否解析容器内网络别名,最稳健。
- **`url` 模式(云端推荐)**:直接把图片 URL 交给模型服务自行下载。云端 DashScope 要求该 URL **公网可达**(内网 `host.docker.internal` 不行,需公网域名)。

> 因此默认 `VLM_IMAGE_MODE=base64`(配合本地 Ollama)。切云端且图片有公网地址时用 `url`,否则仍用 `base64`。

### 3.3 `describe_image()` 实现(`llm.py` 新增)

```python
import base64
import urllib.request

# VLM client（与 _chat_client/_embed_client 同构）—— 本地主
_vlm_client = OpenAI(
    api_key=settings.VLM_API_KEY or "ollama",
    base_url=settings.VLM_BASE_URL,
)

# VLM 云端降级 client（本地失败时兜底；VLM 输出是文字，可自由换模型）
_vlm_fallback_client = OpenAI(
    api_key=settings.VLM_FALLBACK_API_KEY or "missing",
    base_url=settings.VLM_FALLBACK_BASE_URL,
) if settings.VLM_FALLBACK_ENABLED else None

_VLM_SYS = (
    "你是校园物品识别助手。请根据图片(以及用户文字,如有)识别物品并提取结构化特征。"
    "只输出 JSON,格式:"
    '{"category":"物品类别","color":"颜色","brand":"品牌","model":"型号/版本",'
    '"condition":"成色/状态","features":["显著特征"],"description":"一句话综合描述"}。'
    "未知字段留空字符串或空数组,不要编造,不要输出多余文字。"
)

def _fetch_image_base64(image_url: str) -> str:
    """graphrag 容器侧拉取图片字节并转 base64(零额外依赖,用标准库)。"""
    with urllib.request.urlopen(image_url, timeout=settings.VLM_TIMEOUT) as r:
        return base64.b64encode(r.read()).decode()

def describe_image(image_url: str, user_text: str = "", intent: str = "") -> dict:
    """读图 → 结构化物品描述。VLM 关闭或失败时返回 {}。"""
    if not settings.VLM_ENABLED or not image_url:
        return {}
    if settings.VLM_IMAGE_MODE == "base64":
        b64 = _fetch_image_base64(image_url)
        url_field = f"data:image/jpeg;base64,{b64}"
    else:
        url_field = image_url

    user_content = [
        {"type": "text", "text": f"用户描述:{user_text or '(无)'}\n意图:{intent or '(未知)'}\n请识别该物品并按要求输出 JSON。"},
        {"type": "image_url", "image_url": {"url": url_field}},
    ]
    def _call(client, model):
        resp = client.chat.completions.create(
            model=model,
            messages=[{"role": "system", "content": _VLM_SYS},
                      {"role": "user", "content": user_content}],
            temperature=0.0, timeout=settings.VLM_TIMEOUT,
        )
        return (resp.choices[0].message.content or "").strip()
    try:
        # 本地优先 VLM，失败降级云端 VLM（复用 llm.py 同款 _with_fallback）
        raw = _with_fallback(
            "vlm",
            lambda: _call(_vlm_client, settings.VLM_MODEL),
            (lambda: _call(_vlm_fallback_client, settings.VLM_FALLBACK_MODEL))
            if _vlm_fallback_client else None,
        )
        # 复用 extract_triples 同款去 code-fence 逻辑
        if raw.startswith("```"):
            raw = raw.split("```", 2)[1]
            if raw.startswith("json"):
                raw = raw[4:]
            raw = raw.strip()
        return json.loads(raw)
    except Exception as e:  # noqa: BLE001
        logger.warning("VLM describe_image 本地+云端均失败: %s", e)
        return {}
```

### 3.4 图文融合(对应四个场景)

在 `07` 的入库流程中,对每张图调 `describe_image`,然后融合:

- **有文字(场景 1/3)**:以用户文字为主干,把 VLM 的 `features`/`brand`/`color` 等**补充**进去,得到比用户原文更丰富的 `description`(图片揭示的额外特征)。
- **无文字(场景 2/4)**:直接用 VLM 的 `description` 作为帖子物品描述(如书名+版本)。

融合后的 `description` 文本将在 `07` 中向量化入库,供 [`08`](./08-AI智能推荐与问答.md) 检索匹配。

### 3.5 脱敏(`sanitize.py`)

VLM 输出可能包含图片里出现的手机号/二维码文字等。新建 `graphrag/app/sanitize.py`,从 data-pipeline 的 `desensitize.py` 移植 `scrub_text` 与正则(手机/身份证/银行卡/邮箱/QQ/微信/学号/宿舍),对 `description` 与用户文字统一 `scrub_text` 后再入库。**联系方式不进图谱明文**(详见 `07`)。

## 八、风险与待确认项

1. **本地显存/性能**:qwen2.5vl:7b 在 GB10 上的推理延迟决定发帖入库的异步耗时;若过慢可换 `minicpm-v` 或降到云端。
2. **取图网络**:本地 Ollama 用 `base64` 模式时,graphrag 容器必须能访问 `host.docker.internal:8080`(docker-compose 已配 `extra_hosts`);需联调确认。
3. **图片格式**:`_fetch_image_base64` 固定标了 `image/jpeg`,如有 png/webp 可从响应头 `Content-Type` 推断 MIME。
4. **VLM 输出稳定性**:模型偶尔不返回纯 JSON,已用去 code-fence + try/except 兜底为 `{}`;必要时加一次重试或 few-shot 示例。
