# 05 · 组队板块

> 依赖 [`01-板块分类体系-基础架构.md`](./01-板块分类体系-基础架构.md)。本篇重点是**头像叠放组件**与"不显示人数数字"的交互。

## 一、概述

### 目标
组队板块(`code=team`)用于发起组队(打球、比赛、拼车、项目等)。核心交互:

1. **头像叠放效果**:用叠放的成员头像表达"已有哪些人加入",**不展示干瘪的数字**(如 "3/5 人")。
2. **联系方式**:展示并可一键复制(同 `02`),尺寸适中。

### 对应需求原文
> 组队(头像叠放效果)不需要展示干瘪的数字(如 3/5人),联系方式的大小。

## 二、现状与可复用资产

| 资产 | 位置 | 复用点 |
|------|------|--------|
| 组件目录 | `campus-wall-frontend/src/components/`(现有 `CustomTabBar`、`my-navbar`) | 新增 `AvatarStack` |
| 用户头像 URL | `PostVO.userAvatar` 等(现有帖子作者信息) | 头像来源 |
| 复制 | `copyContact`(见 `02`) | 联系方式复制 |
| `contact` 字段 | `post` 表(`01/V3.3`) | 联系方式 |

> ⚠️ 当前**没有**"组队成员表",头像叠放的成员数据源需确认(见 [八](#八风险与待确认项))。

## 三、技术方案(如何实现)

### 3.1 头像叠放组件 `AvatarStack.vue`(不显示数字)

新建 `src/components/AvatarStack/AvatarStack.vue`:

```vue
<template>
  <view class="avatar-stack">
    <image
      v-for="(a, i) in displayAvatars"
      :key="i"
      :src="a || defaultAvatar"
      class="stack-avatar"
      :style="{ marginLeft: i === 0 ? '0' : overlap, zIndex: displayAvatars.length - i }"
      mode="aspectFill"
    />
    <!-- 注意:刻意不渲染 "+N" 或 "3/5" 等数字,仅叠放头像 -->
  </view>
</template>

<script setup>
import { computed } from 'vue'
const props = defineProps({
  avatars: { type: Array, default: () => [] },
  max:     { type: Number, default: 5 },        // 最多展示几个头像
  overlap: { type: String, default: '-18rpx' }, // 叠放重叠量
})
const defaultAvatar = '/static/default-avatar.png'
const displayAvatars = computed(() => props.avatars.slice(0, props.max))
</script>

<style scoped>
.avatar-stack { display: flex; align-items: center; }
.stack-avatar {
  width: 56rpx; height: 56rpx;
  border-radius: 50%;
  border: 2rpx solid #fff;       /* 白描边突出叠放层次 */
  background: #eee;
}
</style>
```

### 3.2 在卡片 / 详情使用

`index.vue` 与 `detail.vue` 中 `post.boardCode === 'team'` 时:

```vue
<view v-if="post.boardCode === 'team'" class="team-info">
  <AvatarStack :avatars="post.memberAvatars" :max="5" />
  <view v-if="post.contact" class="team-contact" @tap.stop="copyContact(post.contact)">
    <text>联系:{{ post.contact }}</text>
    <text class="copy-btn">复制</text>
  </view>
</view>
```

`post.memberAvatars` 为字符串数组(头像 URL),由后端在 `PostVO` 中按所选数据源填充。

### 3.3 成员数据源(两方案,择一)

- **方案 A(MVP,零新表)**:`memberAvatars` 复用"点赞/收藏该帖的用户头像"或仅"发起人头像 + 占位",`PostConverter` 组装。改动小,但语义弱(点赞≠加入)。
- **方案 B(完整,新增表)**:新增 `team_member(post_id, user_id)` 表,用户点"加入组队"写入;`memberAvatars` = 该帖成员头像。语义准确,需新增加入接口与按钮。

```sql
-- 方案 B 可选:V3.5__team_member.sql
CREATE TABLE IF NOT EXISTS team_member (
    id          bigint auto_increment PRIMARY KEY,
    post_id     bigint NOT NULL,
    user_id     bigint NOT NULL,
    create_time datetime DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_team_member UNIQUE (post_id, user_id)
) charset=utf8mb4 COMMENT '组队成员表';
CREATE INDEX idx_tm_post ON team_member (post_id);
```

## 四、数据模型 / 接口

- `PostVO` 增 `memberAvatars`(`List<String>`,头像 URL 列表);`contact` 复用。
- 方案 B 另需:`team_member` 表、`POST /api/v1/posts/{id}/join`(加入组队)、`GET` 时按 `post_id` 聚合成员头像。
- 接口:列表/详情响应在 `boardCode === 'team'` 时带 `memberAvatars`。

## 五、改动清单

| 端 | 文件 | 改动 |
|----|------|------|
| 前端 | `components/AvatarStack/AvatarStack.vue`(新建) | 头像叠放组件,不显示数字 |
| 前端 | `pages/index/index.vue` / `pages/post/detail.vue` | 组队分支用 `AvatarStack` + 联系方式复制 |
| 后端 | `community/service/impl/PostConverter.java` | 组装 `memberAvatars`(按所选数据源) |
| 后端(方案 B) | `community/...`(新建 service/mapper) + `V3.5__team_member.sql` | 成员表 + 加入接口 |

## 六、实现步骤

1. 新建 `AvatarStack.vue` 组件,确认叠放效果、无数字。
2. 后端确定成员数据源(A 或 B),`PostConverter` 输出 `memberAvatars`。
3. 前端组队分支接入组件 + 联系方式复制。
4. (方案 B)实现"加入组队"接口与按钮。
5. 联调:组队帖展示叠放头像、无 "3/5" 数字、联系方式可复制。

## 七、验收标准

- [ ] 组队帖以叠放头像展示成员,**不出现** "3/5人" 之类数字。
- [ ] 头像有白描边、按层叠放,超出 `max` 的不再展示(也不显示 "+N")。
- [ ] 联系方式展示且可一键复制。

## 八、风险与待确认项

1. **成员数据源**(关键):采用方案 A(点赞头像兜底,MVP)还是方案 B(新增 `team_member` 表 + 加入按钮)?直接影响是否新增表与接口,需产品确认。
2. **"联系方式的大小"**:需求此句表述不完整,理解为"组队帖也展示联系方式,尺寸适中"。最终样式以设计稿为准。
3. **满员/截止**:是否需要"已满""已截止"状态?本期未含,可后续迭代。
