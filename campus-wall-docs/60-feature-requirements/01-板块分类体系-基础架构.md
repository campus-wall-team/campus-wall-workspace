# 01 · 板块分类体系 — 基础架构

> 本篇是「帖子板块分类系统」的**底座文档**。`02`~`05` 各板块文档都依赖本篇定义的板块建模、标签体系、发布流程与列表筛选。先实现本篇,再实现各板块的差异化字段与视觉。

> ✅ **已实现(2026-06-10)**:Flyway `V3.2~V3.4` 已落库(本机 MySQL 8.0.46 实测支持 `ADD COLUMN/CREATE INDEX IF NOT EXISTS`);`topic` 顶级分组重映射为 5 板块并带 `code`,旧分组(日常/学习/交友/活动)`code` 置空、前端不渲染;`BoardType` 枚举、`Tag/PostTag` 实体与 Mapper、`PostDTO/PostVO` 字段均已就绪;二级筛选走 `post_tag` join + 旧帖 `ai_tags` LIKE 双路兜底。**标签纯运营预置**:用户自定义标签只写入 `post.ai_tags`、不建档进 `tag` 表,前端点击他人自定义标签提示"无法跳转,请选择预置标签"。

## 一、概述

### 背景与目标
在帖子主页 `index.vue` 的一级分类(topic)中,落地 **5 个板块**,并建立"板块(父类)→ 标签(子类)"的两级分类体系:

| # | 板块 | code | 说明 |
|---|------|------|------|
| 1 | 推荐 | `recommend` | 存放**所有**帖子,除置顶外按时间线从新到旧排序;**不可**作为发布目标 |
| 2 | 二手交易 | `secondhand` | 发布时必须填**价格**;联系方式可选(详见 `02`) |
| 3 | 兼职发布 | `parttime` | 发布时填**薪资 / 信息费**;联系方式可选(详见 `03`) |
| 4 | 推广 | `promotion` | 广告帖,视觉差异化 + Banner 大图(详见 `04`) |
| 5 | 组队 | `team` | 头像叠放、不显示人数数字(详见 `05`) |

> ⚠️ 需求原文标题写"四大分类",实际列举了 **5 个**(推荐/二手交易/兼职发布/推广/组队)。本系列按 **5 个板块**实现。

### 对应需求原文
- 需求 1:在帖子主页 index.vue 的第一级 topic 增添分类。
- 需求 2:这五大类的子类会存在一些标签(如 `#测试`);帖子可以标签形式携带,用户打上某标签后,可在对应父类的子类中直接看到该帖。
- 需求 3:父类只能在帖子发布页选择(决定发布到哪个板块);如选二手交易类需输入价格才能发布;标签任意。
- 推荐类:存放所有帖子,除置顶外按时间线从头到尾排序。

## 二、现状与可复用资产

**项目已存在一套两级分类机制,本需求是在其上做"语义重映射 + 差异化扩展",而非从零搭建。**

| 现状 | 位置 | 说明 |
|------|------|------|
| 一级父板块 = `post.category` 字符串 | `db/migration/V3.0__baseline.sql:58` | `varchar(50)` 默认 `'日常'`,已建索引 `idx_post_category` |
| 分类字典 = `topic` 自关联表 | `V3.0__baseline.sql:132` | `parent_id` NULL=顶级分组,有 `name`(唯一 `uk_name`)、`sort_order`、`post_count`、`icon`;**无 `code` 字段** |
| 标签 = `post.ai_tags` 逗号分隔串 | `V3.0__baseline.sql:64` | `varchar(255)`;**无独立 tag 表/关联表**,现用 `LIKE` 模糊统计(性能差) |
| 一级/二级 tab 渲染 | 前端 `pages/index/index.vue` | `fetchCategories()` 调 `categoryApi.getGroups()`;`selectGroup()` 切父板块(推荐→传空串)、`selectCategory()` 切子标签 |
| 分组数据接口 | 后端 `community/.../CategoryController` + `TopicServiceImpl.getGroupedCategories` | 返回 `[{id,name,icon,postCount,children:[...]}]` |

| 发布页 | 前端 `pages/publish/publish.vue` | 已有"分区/标签"选择器;**已 `filter(g => g.name !== '推荐')`**——推荐不可发布,与需求 3 吻合;`submitPost` POST `/api/v1/posts/publish` |
| 发布服务 | `community/service/impl/PostPublishService.publishPost` | `@Transactional`,接收 `PostDTO` |
| VO 映射 | `community/service/impl/PostConverter` | `BeanUtils.copyProperties(post, vo)`——**Post 与 PostVO 同名加字段即自动带出**,零成本 |

**关键结论**:
- 「推荐 = 全量时间线」**已实现**(`category=='推荐'` → 不加 category 过滤)。
- 「父类只能发布页选」**已实现**(发布页过滤掉推荐)。
- 本篇主要新增:① `topic.code` 机器标识 + `BoardType` 枚举;② 规范化 `tag`/`post_tag` 标签表;③ `post.is_top` 置顶;④ 板块字典数据重映射。

## 三、技术方案(如何实现)

### 3.1 板块建模:复用「字典表 + category 字符串」,新增 code 机器标识

**决策:不引入 Java 硬枚举约束板块的增减**(否则运营加板块要改代码重新部署),继续用 `topic` 顶级分组(字典)+ `post.category`(字符串)。仅新增两样东西:

1. 给 `topic` 表(顶级分组)加 `code` 字段(`recommend/secondhand/parttime/promotion/team`),供**前端识别板块类型**做差异化渲染、供**后端**做条件校验。
2. 新增枚举 `BoardType` 承载"板块 → 业务行为"的元数据(是否需要价格/薪资等),后端用它做校验 `switch`,避免用中文名硬比较(中文名可能被运营改坏)。

```
前端渲染/判断  ← topic.code(随接口下发)
后端条件校验    ← BoardType(由 category 名 / code 反查)
数据过滤        ← post.category(字符串,已有索引)
```

### 3.2 标签(子类)体系:新建 tag / post_tag 关联表

需求 2 要求"标签隶属于某父板块,打标签后能在对应父类的子类中看到"。现有 `ai_tags` 字符串 + 全表 `LIKE` 既慢又无法表达"标签归属哪个板块"。**新建规范化表**:

- `tag`:标签字典,`board_code` 标明所属父板块。
- `post_tag`:帖子-标签多对多关联,冗余 `tag_name` 便于列表免 join 直接展示。
- 保留 `post.ai_tags` 兼容旧数据与全文搜索(双写)。

二级筛选(父板块 + 标签)= `post JOIN post_tag WHERE post.category=? AND post_tag.tag_name=?`,走 `tag_id`/`tag_name` 索引,远优于 `LIKE`。

### 3.3 发布页选板块 + 标签

- 发布页板块选择器数据来自 `categoryApi.getGroups()`(已过滤推荐)。选择器项需带上 `code`,以便选不同板块时**动态渲染对应字段区**(价格/薪资/联系方式/Banner —— 由 `02`~`05` 实现)。
- 标签"任意":用户可从该板块下已有 `tag` 多选,也可输入自定义标签(沿用现有 `customTags`)。提交时:
  - `category` = 所选板块 `name`;
  - 自定义标签若不存在则在 `tag` 表按 `board_code` 自动建档;
  - 写入 `post_tag` 关联,同时把标签名同步进 `post.ai_tags`(双写兼容)。

### 3.4 列表二级筛选 + 推荐类置顶

- 一级:点板块 → `category`(推荐传空)。
- 二级:点标签 → `tag`,后端改走 `post_tag` join(替换 `ai_tags` LIKE)。
- 推荐类排序:新增 `post.is_top`,列表 `orderByDesc(is_top).orderByDesc(create_time)`,实现"除置顶外按时间线"。

### 3.5 数据流图

```
发帖:
 publish.vue ──选板块(category+code)+标签── POST /api/v1/posts/publish
      └─> PostPublishService.publishPost(@Transactional)
            ├─ BoardType.fromCategory(category) 校验必填字段(02~05)
            ├─ 写 post(category, is_top=0, 扩展字段...)
            ├─ upsert tag(按 board_code) + 写 post_tag
            └─ 同步 ai_tags(双写)

浏览:
 index.vue ──category(空=推荐)/tag── GET /api/v1/posts/list
      └─> PostQueryService.getPostList
            ├─ category!='' → eq(category)
            ├─ tag!='' → JOIN post_tag WHERE tag_name=tag
            └─ orderBy is_top DESC, create_time DESC
```

### 4.2 后端枚举 `BoardType`(新建 `community/enums/BoardType.java`)

```java
package com.jyu.campus.community.enums;

public enum BoardType {
    RECOMMEND ("recommend",  "推荐",     false, false),
    SECONDHAND("secondhand", "二手交易", true,  false),  // 需价格
    PARTTIME  ("parttime",   "兼职发布", false, true),   // 需薪资
    PROMOTION ("promotion",  "推广",     false, false),
    TEAM      ("team",       "组队",     false, false);

    private final String code;
    private final String displayName;
    private final boolean requirePrice;
    private final boolean requireSalary;

    BoardType(String code, String displayName, boolean requirePrice, boolean requireSalary) {
        this.code = code; this.displayName = displayName;
        this.requirePrice = requirePrice; this.requireSalary = requireSalary;
    }
    public String getCode() { return code; }
    public boolean isRequirePrice()  { return requirePrice; }
    public boolean isRequireSalary() { return requireSalary; }

    /** 按板块中文名(post.category)反查,未命中默认 RECOMMEND */
    public static BoardType fromCategory(String name) {
        if (name != null) for (BoardType b : values())
            if (b.displayName.equals(name)) return b;
        return RECOMMEND;
    }
    public static BoardType fromCode(String code) {
        if (code != null) for (BoardType b : values())
            if (b.code.equals(code)) return b;
        return RECOMMEND;
    }
}
```
