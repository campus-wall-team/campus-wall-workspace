# campus-wall-ops 开发/运维文档

## 项目简介

campus-wall-ops 是校园墙项目的运维基础设施仓库，采用"基础设施即代码"理念，通过 Docker Compose 编排所有依赖服务，提供完整的监控告警体系和反向代理配置。

**包含内容**：
- Docker Compose 编排（17 个活跃服务，Chroma 已下线、cadvisor 整段注释保留）
- Prometheus 监控配置
- Grafana 面板配置
- Alertmanager 告警路由
- Nginx 反向代理
- systemd 服务配置

## 技术栈

| 技术 | 版本 | 用途 |
|------|------|------|

## 快速开始

### 1. 环境要求

- Docker Desktop 或 Docker Engine
- Docker Compose v2+
- 内存：8GB+（所有容器约需 5.5GB）

### 2. 配置环境变量

```bash
cd campus-wall-ops
cp .env.example .env
```

编辑 `.env`，配置关键变量：

```env
# 数据库密码（生产环境必须修改）
MYSQL_ROOT_PASSWORD=your_secure_password
REDIS_PASSWORD=your_secure_password
NEO4J_PASSWORD=your_secure_password
MINIO_SECRET_KEY=your_secure_password

# Grafana 管理员密码
GF_SECURITY_ADMIN_PASSWORD=your_admin_password

# 告警 Webhook（企业微信/钉钉）
ALERT_WEBHOOK=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx
ALERT_CHANNEL=wecom

# MySQL Exporter 账号
MYSQLD_EXPORTER_PASSWORD=exporter_password
```

### 3. 启动所有服务

```bash
# 前台启动（查看日志）
docker-compose up

# 后台启动
docker-compose up -d

# 查看状态
docker-compose ps

# 查看日志
docker-compose logs -f [服务名]
```

### 4. 访问服务

| 服务 | 地址 | 说明 |
|------|------|------|
| Nginx (监控UI) | http://localhost:8090 | 统一入口 |
| Prometheus | http://localhost:9090 | 指标查询 |
| Grafana | http://localhost:3000 | 可视化面板 |
| Alertmanager | http://localhost:9093 | 告警管理 |
| MySQL | localhost:3306 | 数据库 |
| Redis | localhost:6379 | 缓存 |
| MinIO | localhost:9000/9001 | 对象存储 |
| Neo4j (prod) | localhost:7475/7688 | 知识图谱（HTTP/Bolt） |
| Neo4j (test) | localhost:7690/7689 | 知识图谱（test 环境隔离） |
| Neo4j (dev) | localhost:7692/7691 | 知识图谱（dev 环境隔离） |

### 5. 停止服务

```bash
# 停止（保留数据）
docker-compose down

# 停止并删除数据卷（慎用）
docker-compose down -v
```

### 应用层（2个）

| 服务 | 构建方式 | 端口 | 用途 |
|------|----------|------|------|
| ai-api | 构建上下文 `../campus-wall-ai`（原 graphrag 服务已并入） | 8011 | AI 知识图谱服务（FastAPI + LangGraph） |
| ai-memory-worker | 同镜像 `campus-wall-ai:2.0.0`，独立进程 | — | 消费 Redis Streams 做异步记忆提取 |

> **campus-wall-ai 构建/运行说明**（原 campus-wall-graphrag 已并入 campus-wall-ai，端口 8011；旧 graphrag 的 8001 已下线）：构建上下文为兄弟子模块 `../campus-wall-ai`（含 Dockerfile + app 源码，原 graphrag 的图谱/向量/LLM/脱敏代码迁入 `app/graphrag/`，HTTP 契约端点原样保留在 `app/main.py`）。服务以 `network_mode: host` 运行（无端口映射，仍监听 8011），host 网络下用 localhost 直达 Ollama/后端。容器部署侧 `.env` 把 CHAT 改走**内网 Qwen3.6-35B（172.21.160.101:8003）**；并新增 `VLM_*`（qwen2.5vl:7b 图片理解，本地优先 + 云端 qwen-vl-plus 降级）、`BACKEND_BASE_URL`（拼 `/api/v1/files/view` 取帖子图片）等环境变量。

## Prometheus 配置

### 采集目标

```yaml
scrape_configs:
  # Prometheus 自身
  - job_name: 'prometheus'
    static_configs:
      - targets: ['localhost:9090']

  # 主机指标
  - job_name: 'node-exporter'
    static_configs:
      - targets: ['campus-node-exporter:9100']

  # Java 后端（宿主机）
  - job_name: 'campus-wall'
    static_configs:
      - targets: ['host.docker.internal:8080']
    metrics_path: '/actuator/prometheus'

  # Redis
  - job_name: 'redis'
    static_configs:
      - targets: ['campus-redis-exporter:9121']

  # MySQL
  - job_name: 'mysql'
    static_configs:
      - targets: ['campus-mysqld-exporter:9104']

  # 探针检测
  - job_name: 'blackbox'
    metrics_path: /probe
    params:
      module: [http_2xx]
    static_configs:
      - targets:
        - http://campus-minio:9000/minio/health/live
        - http://host.docker.internal:8011/health
        - http://campus-neo4j:7474
```

> blackbox 探针共 **3 个目标**：minio:9000/minio/health/live、host.docker.internal:8011/health（campus-wall-ai，原 graphrag；服务跑 host 网络，容器名 campus-graphrag:8001 无法解析，故改用 host.docker.internal:8011）、neo4j:7474（Chroma 已下线，无相关探针）。

### 告警规则

**8 条规则，分 4 组**（service-availability / host-resources / application / business）：

| 分组 | 规则 | 阈值 | severity |
|------|------|------|----------|
| service-availability | ServiceDown | 服务不可达 | critical |
| service-availability | BlackboxProbeFailed | 探针失败 | critical |
| host-resources | HostHighMemory | 内存使用率 > 90% | warning |
| host-resources | HostHighDisk | 磁盘使用率 > 85% | warning |
| host-resources | HostHighCPU | CPU 使用率 > 90% | warning |
| application | JvmHeapHigh | JVM Heap > 90% | warning |
| application | HttpServerErrorRateHigh | 5xx 率 > 5% | warning |
| business | ModerationBacklog | 待审核 > 50 | warning |

## Nginx 配置

```nginx
server {
    listen 80;

    # 管理后台 SPA
    location / {
        root /usr/share/nginx/html;
        try_files $uri $uri/ /index.html;
    }

    # API 代理到 Java 后端
    location /api/ {
        proxy_pass http://host.docker.internal:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # Grafana 代理（带子路径，需配 GF_SERVER_SERVE_FROM_SUB_PATH）
    location /grafana/ {
        proxy_pass http://campus-grafana:3000/grafana/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

## 生产部署建议

1. **修改默认密码**：所有服务的默认密码在生产环境必须修改
2. **启用 HTTPS**：Nginx 配置 SSL 证书
3. **限制端口暴露**：仅暴露 80/443，其他服务通过内网访问
4. **定期备份**：MySQL 和 Neo4j 数据定期备份
5. **日志轮转**：配置 Docker 日志驱动和轮转策略
6. **监控告警**：确保告警渠道配置正确并测试

## 常见问题

### Q: 容器启动失败？

```bash
# 查看具体错误
docker-compose logs [服务名]

# 常见原因：
# - 端口冲突：检查本地端口是否被占用
# - 内存不足：检查 docker-compose.override.yml 的内存限制
# - 权限问题：Docker 需要管理员权限
```

### Q: Java 后端无法被 Prometheus 采集？

确保：
1. Java 后端已启动
2. `application.yaml` 中暴露 prometheus 端点：
   ```yaml
   management.endpoints.web.exposure.include: health,info,prometheus,metrics
   ```
3. Prometheus 配置中使用了 `host.docker.internal:8080`

### Q: Grafana 面板没有数据？

1. 检查 Prometheus 数据源是否配置正确
2. 检查 Prometheus 是否能正常采集目标
3. 检查面板的查询语句是否正确

### Q: 告警不触发？

1. 检查 Alertmanager 配置中的 webhook URL
2. 检查告警规则表达式
3. 检查 alert-adapter 服务是否正常运行
4. 在 Prometheus 中手动测试告警表达式
