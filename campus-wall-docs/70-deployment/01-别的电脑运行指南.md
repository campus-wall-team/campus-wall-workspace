# 70 · 别的电脑运行 campus-wall 指南（板块分类 + AI 多模态）

> 面向"换一台电脑/拉新同学进组"的实操手册。讲清楚:**哪台机器跑什么、怎么连内网中间件、怎么把项目跑起来并验证 AI 闭环**。配合 [`../60-feature-requirements/`](../60-feature-requirements/) 阅读。

## 一、部署拓扑（重要）

本项目采用 **「中间件集中在 GB10 服务器 + 前后端各自机器连内网开发」** 的模式:

```
┌───────────── GB10 服务器（本机，内网 IP 172.21.160.212）─────────────┐
│ Docker 容器: MySQL:3306 · Redis:6379 · MinIO:9000/9001 · Neo4j(Bolt 7688)│
│             · Chroma:8000 · graphrag:8001 · 监控栈(Prometheus/Grafana…) │
│ 宿主机进程: Ollama:11434 (qwen2.5:7b / bge-m3 / qwen2.5vl:7b)            │
└──────────────────────────────────────────────────────────────────────┘
        ▲ 连内网 IP                                  ▲ 连内网 IP
┌───────┴────────┐                          ┌────────┴─────────┐
│ 后端开发机      │  HTTP :8080 给前端       │ 前端开发机        │
│ Java 17 + Maven │ ───────────────────────▶ │ Node 18+ uni-app  │
│ Spring Boot jar │                          │ 微信开发者工具/H5 │
└────────────────┘                          └──────────────────┘
```

> 三种角色可以是同一台机器,也可以分开。下文按"GB10 中间件机"+"后端机"+"前端机"分别说明;同机部署时把内网 IP 换成 `localhost` 即可。

## 二、代码获取（任意机器）

仓库是 **根仓库 + 7 个 git 子模块**。务必带 `--recurse-submodules`:

```bash
git clone --recurse-submodules <根仓库地址> campus-wall
cd campus-wall
# 已克隆但子模块为空时:
git submodule update --init --recursive
```

目录速览(均为根仓库下的兄弟子模块):
- `campus_wall/` —— Java 后端
- `campus-wall-graphrag/` —— Python AI 服务(FastAPI)
- `campus-wall-frontend/` —— uni-app 小程序前端
- `campus-wall-ops/` —— Docker Compose 编排 + graphrag 部署侧 `.env`
- `campus-wall-docs/` —— 文档(本目录所在,属根仓库)

## 三、GB10 中间件机：启动数据层 + AI 服务

> 若你就是在这台 GB10 上操作,中间件多数已常驻;以下命令幂等可重复执行。

### 3.1 启动数据层与 graphrag 容器

```bash
cd campus-wall/campus-wall-ops
# 准备 graphrag 的本地 .env（密钥不入库；从模板复制后按需填写）
cp graphrag-service/.env.example graphrag-service/.env   # 已存在则跳过

# 启动（override 里若含未定义服务 cadvisor 会报错，用 -f 仅主文件更稳）
docker compose -f docker-compose.yml up -d
# 仅(重)构建启动 graphrag：
docker compose -f docker-compose.yml up -d --build graphrag
```

关键端口(对外):MySQL `3306`、Redis `6379`、MinIO `9000/9001`、Neo4j HTTP `7475`/Bolt `7688`、Chroma `8000`、**graphrag `8001`**。

> ⚠️ graphrag 容器构建上下文已指向同级 `../campus-wall-graphrag`(含 Dockerfile),不是 `graphrag-service/`。
> ⚠️ 若 8001 被宿主机上以前手动起的 `uvicorn` 占用,先停掉那个进程再起容器(`ss -ltnp | grep 8001` 查 PID)。

### 3.2 本地大模型（Ollama，宿主机进程）

```bash
# 安装(若没有)：curl -fsSL https://ollama.com/install.sh | sh
ollama list                 # 需含: qwen2.5:7b（CHAT）、bge-m3（EMBED）、qwen2.5vl:7b（VLM）
ollama pull qwen2.5vl:7b    # 缺视觉模型时拉取（约 6GB），AI 读图功能依赖它
```

> graphrag 容器经 `host.docker.internal:11434` 回访宿主机 Ollama(compose 已配 `extra_hosts`)。纯本地运行,云端降级默认关闭(`*_FALLBACK_ENABLED=false`);如需云端兜底,在 `graphrag-service/.env` 填 `DASHSCOPE_API_KEY` 并打开对应 `*_FALLBACK_ENABLED`。

> ⚠️ **关键(实测踩坑)**:Ollama 默认只监听 `127.0.0.1:11434`,**Docker 容器(经网关 172.17.0.1)连不上**,会导致 graphrag 入库/检索报 `Connection error`(且 embedding 无云端降级、必须本地可用)。**必须让 Ollama 监听 `0.0.0.0`**:
> ```bash
> # systemd 管理时：
> sudo systemctl edit ollama      # 添加：[Service]\nEnvironment="OLLAMA_HOST=0.0.0.0:11434"
> sudo systemctl daemon-reload && sudo systemctl restart ollama
> # 手动 serve 时：
> OLLAMA_HOST=0.0.0.0:11434 ollama serve
> # 验证：ss -ltnp | grep 11434 应显示 0.0.0.0:11434
> ```
> 本项目本闭环已在 GB10 上用 `--network host` 实测跑通(入库 `indexed:true`、"有没有人捡到蓝色书包"→召回对应帖 score≈0.91);容器+`extra_hosts` 部署务必先放开 Ollama 监听。

### 3.3 验证 graphrag

```bash
curl http://localhost:8001/health                      # {"status":"ok","neo4j":true}
# 入库一条测试帖（VLM 读图 + 向量化 → Neo4j Post/Item）
curl -s http://localhost:8001/ingest-post -H 'Content-Type: application/json' -d '{
  "post_id": 999001, "intent": "lost_found", "category": "推荐",
  "text": "在图书馆捡到一个蓝色双肩书包", "images": [], "tags": ["失物"]
}'
# 自然语言召回
curl -s http://localhost:8001/match-posts -H 'Content-Type: application/json' -d '{
  "question": "有没有人捡到蓝色的书包", "topK": 5
}'
```

## 四、后端机：运行 Java 后端

需 **JDK 17**。后端通过环境变量连 GB10 内网中间件(默认值见 `application-dev.yaml`,务必用 env 覆盖)。

```bash
cd campus-wall/campus_wall

# 用 GB10 内网地址覆盖中间件连接（同机部署改成 localhost）
export GB10=172.21.160.212
export MYSQL_URL="jdbc:mysql://$GB10:3306/campus_wall?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&createDatabaseIfNotExist=true"
export MYSQL_USER=root
export MYSQL_PASSWORD=<GB10 MySQL 密码>          # 见 ops/.env 的 MYSQL_ROOT_PASSWORD
export REDIS_HOST=$GB10  REDIS_PASSWORD=<redis 密码>
export MINIO_ENDPOINT="http://$GB10:9000" MINIO_ACCESS_KEY=root MINIO_SECRET_KEY=<minio 密钥>
export GRAPHRAG_BASE_URL="http://$GB10:8001"
export APP_BASE_URL="http://<本机或网关地址>:8080"

# 构建并运行
./mvnw -DskipTests package
java -jar target/campus-wall-0.0.1-SNAPSHOT.jar --spring.profiles.active=dev
```

启动时 **Flyway 自动应用 `V3.2~V3.5`** 迁移(板块/标签/扩展字段/组队成员表);幂等,重复启动不报错。后端监听 `:8080`。

> graphrag 容器取帖子图片走 `BACKEND_BASE_URL`(默认 `host.docker.internal:8080`)。若后端不在 GB10 上,需把容器的 `BACKEND_BASE_URL` 指向后端可达地址(改 `graphrag-service/.env` 后 `docker compose up -d graphrag`)。

## 七、常见问题

| 现象 | 处理 |
|------|------|
| `docker compose up` 报 `cadvisor has neither image nor build` | 用 `-f docker-compose.yml` 跳过 override,或在 override 注释 cadvisor |
| graphrag 起不来:8001 被占用 | 宿主机有旧 `uvicorn` 进程,`ss -ltnp \| grep 8001` 找 PID 停掉再起容器 |
| graphrag 连不上 Neo4j | 容器内用 `bolt://campus-neo4j:7687`(compose 注入),不是宿主机的 7688 |
| VLM/Embed 调用失败 | 确认宿主机 `ollama list` 含 `qwen2.5vl:7b`/`bge-m3`,且 11434 可达 |
| 后端 Flyway 失败 | 确认连的是带 `V3.0/V3.1` 的 campus_wall 库;`flyway_schema_history` 可查已应用版本 |
| 前端请求 401/跨域 | 检查 `VITE_API_BASE_URL` 指向正确后端;小程序勾选不校验域名;后端 CORS 配置 |
| Node 版本过低构建失败 | uni-app(Vite)需 Node 18+,用 nvm 切换 |

## 八、最简拓扑：中间件全在 GB10(A 机)，B 机只跑「前端 + 后端」

这是最常用的开发姿势:**A 机(本机 GB10, `172.21.160.212`)** 跑全部中间件/DB/graphrag/Ollama;**B 机**只 clone 代码、跑后端 jar + 前端 dev,全部连 A 机内网。

### 第 0 步：先搞清两件事——IP 和「.env 在哪」(纯新手必读)

**(1) 两台机器的 IP**

- **A 机(GB10,跑中间件的那台) = `172.21.160.212`**,固定不变,下文所有命令里的 `$A` 都是它。
- **B 机(你正在操作的这台) = 你自己的 IP**,在 **B 机**上运行下面命令查,认 `172.21.160.` 开头的那个(和 A 机同网段):
  ```bash
  hostname -I        # 输出一串,挑 172.21.160.xxx 那个;没有就试 ip -4 addr | grep 172.21
  ```
  > 本组两台 B 机的 IP 是 `172.21.160.221` 和 `172.21.160.223`,下文凡写 `<本机IP>` 就填你这台 B 机的那个。

**(2) 「.env 文件」到底在哪——别找错了**

| 你以为的 .env | 真相 |
|---------------|------|
| B 机后端要不要 .env? | **不需要,后端没有 .env 文件**。Spring Boot 不读 .env;数据库/Redis 等连接信息靠"环境变量",下文用一个 `run-backend.sh` 脚本统一设置,你只改脚本就行。 |
| B 机前端的 .env? | **要你自己新建一个**(项目里默认没有),内容就两行,第 5 步会给。Vite 启动时自动读它。 |
| 那 ops/.env、graphrag-service/.env? | 这俩**在 A 机(GB10)**,分别放中间件密码和 AI 服务配置,**不用拷到 B 机**,只是取密码时会用到(见下一条)。 |

**(3) 三个中间件密码去哪拿** —— 在 **A 机(GB10)** 上运行(B 机用不了,因为文件在 A 机):
```bash
grep -E 'MYSQL_ROOT_PASSWORD|REDIS_PASSWORD|MINIO_SECRET_KEY' campus-wall-ops/.env
```
把打印出来的三个值,等下填进 B 机的启动脚本对应位置。

### 两个易混变量速查：`APP_BASE_URL`(B 机) 与 `BACKEND_BASE_URL`(A 机)

先记住一个原则:**图片字节一直存在 A 机的 MinIO 里,但"消费方拿到的那串 URL"里写的主机,必须是消费方自己能访问到的地址,绝不能是 `localhost`。** 这两个变量都是在回答"URL 里写哪个 IP"——和图存在哪台机器无关。

| 变量 | 填在哪台机器 | 在哪配置 | 填什么值 | 何时必须 |
|------|------------|---------|---------|---------|
| `APP_BASE_URL` | **B 机(后端)** | `campus_wall/src/main/resources/application-dev.yaml` 的 `app.base-url: ${APP_BASE_URL:http://localhost:8080}` —— **读的是环境变量,不是 .env 文件**;启动 jar 前 `export` 即可(或直接改这行默认值) | **该 B 机自己的 IP**:`http://<本机IP>:8080` | 前端/小程序要显示图片、头像、文件时(几乎总要) |
| `BACKEND_BASE_URL` | **A 机(graphrag 容器)** | graphrag 容器的环境变量(见下方 A 机 `docker run`),当前为 `http://localhost:8080` | **后端所在 B 机的 IP**:`http://<B机IP>:8080` | 仅"带图帖"的 VLM 读图;纯文字帖/板块功能用不到 |

- **为什么 `APP_BASE_URL` 填后端 IP 而不是 MinIO?** 后端默认走代理模式(`MinioUtil.getFileUrl`):前端只连后端一个地址,后端在内部去 A 机 MinIO 取字节回传——既兼容微信小程序域名白名单,又不用把 MinIO 9000 暴露给前端。若不设 `APP_BASE_URL`,会回退成 MinIO 直链,那时改为"前端要能直连 A 机:9000",并不更省事。
- **为什么 `BACKEND_BASE_URL` 不能直接用 MinIO 地址?** 后端发给 graphrag 的入库请求只带 `object_name`(`GraphRagBackend.java`,未传完整 url),graphrag 据此拼 `BACKEND_BASE_URL/api/v1/files/view` 经后端**公开端点**(免 JWT)取图。要让 graphrag 改为直连 MinIO 得改代码并暴露 9000,不划算。

### 本组两台 B 机(`172.21.160.221` / `172.21.160.223`)

- **`APP_BASE_URL` 各填各自 IP**:221 这台填 `http://172.21.160.221:8080`、223 这台填 `http://172.21.160.223:8080`;前端的 `VITE_API_BASE_URL` / `VITE_WS_BASE_URL` 同理各指向自己。
- **防火墙不用为两台分别配**:A 机那条 `from 172.21.0.0/16` 已同时覆盖 221 和 223,无需追加。
- **带图帖的限制(纯文字帖无此限制)**:A 机 graphrag 只有一个 `BACKEND_BASE_URL`,无法同时指向 221 和 223。两台**同时**测 AI 读图时,只有被它指向的那台能成功取图。解决二选一:① 约定"带图入库"只在某一台 B 机上做;② 改后端在入库请求里直接传完整图片 URL(小改动,改后就不再依赖 `BACKEND_BASE_URL`)。板块功能/纯文字帖两台随便用。

### A 机一次性准备(让中间件可被 B 机访问)
1. 容器已绑 `0.0.0.0`(MySQL 3306 / Redis 6379 / MinIO 9000-9001 / Neo4j 7688 / graphrag 8001),MySQL 已有 `root@'%'`(可远程,密码见 ops/.env)。
2. **放行防火墙(ufw active,需 sudo)** —— 允许 B 机/内网访问这些端口:
   ```bash
   sudo ufw allow from 172.21.0.0/16 to any port 3306,6379,9000,9001,8001 proto tcp
   # 若 B 机后端发"带图帖",graphrag(A) 需回访 B 机后端取图,B 机也要放行 8080(见下)
   ```
3. **graphrag 取图地址(带图帖关键)**:graphrag 给图片做 VLM 时,经 `BACKEND_BASE_URL/api/v1/files/view` 取图。**后端在 B 机时**,A 机 graphrag 的 `BACKEND_BASE_URL` 必须指向 B 机后端:
   ```bash
   docker rm -f campus-graphrag
   docker run -d --name campus-graphrag --network host --restart unless-stopped \
     -e NEO4J_URI=bolt://localhost:7688 -e NEO4J_USER=neo4j -e NEO4J_PASSWORD='<neo4j密码>' \
     -e CHAT_BASE_URL=http://localhost:11434/v1 -e EMBED_BASE_URL=http://localhost:11434/v1 \
     -e VLM_ENABLED=true -e VLM_BASE_URL=http://localhost:11434/v1 -e VLM_MODEL=qwen2.5vl:7b \
     -e CHAT_FALLBACK_ENABLED=false -e EMBED_FALLBACK_ENABLED=false -e VLM_FALLBACK_ENABLED=false \
     -e BACKEND_BASE_URL=http://<B机IP>:8080 \
     campus-wall-ops-graphrag
   ```
   > 纯文字帖不取图,`BACKEND_BASE_URL` 无所谓;只有带图帖的 VLM 读图依赖它。多个 B 机各自后端时,graphrag 只能指一个(或让"带图入库"在与 graphrag 同机的后端上做)。
   > 本机当前 graphrag 用 `--network host` 直连 127.0.0.1 的 Ollama,**无需** 改 Ollama 监听。

### 第 1 步：B 机装好这几样(一次性)

```bash
java -version     # 需要 17。没有就装 JDK 17(Ubuntu: sudo apt install openjdk-17-jdk)
node -v           # 需要 >=18。低了用 nvm 装：nvm install 20 && nvm use 20
git --version     # 没有就装 git
```

### 第 2 步：拉代码(务必带子模块)

```bash
git clone --recurse-submodules <根仓库地址> campus-wall
cd campus-wall
# 如果忘了 --recurse-submodules，clone 完补一句：
git submodule update --init --recursive
```

### 第 3 步：跑后端(用一个脚本,不用记一堆命令)

后端没有 .env,我们写个启动脚本。在 `campus-wall/campus_wall/` 目录下**新建文件 `run-backend.sh`**,把下面整段贴进去,然后**改 4 个 `<...>` 占位**(3 个密码来自第 0 步(3),`<本机IP>` 是第 0 步(1)查到的 B 机 IP):

```bash
#!/usr/bin/env bash
set -e
export A=172.21.160.212                          # A 机(GB10)IP，固定，别改
export MYSQL_URL="jdbc:mysql://$A:3306/campus_wall?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true"
export MYSQL_USER=root
export MYSQL_PASSWORD='<填 A 机 MYSQL_ROOT_PASSWORD>'
export REDIS_HOST=$A
export REDIS_PASSWORD='<填 A 机 REDIS_PASSWORD>'
export MINIO_ENDPOINT="http://$A:9000"
export MINIO_ACCESS_KEY=root
export MINIO_SECRET_KEY='<填 A 机 MINIO_SECRET_KEY>'
export GRAPHRAG_BASE_URL="http://$A:8001"
export APP_BASE_URL="http://<本机IP>:8080"        # 填 B 机自己的 172.21.160.x，别用 localhost！
./mvnw -DskipTests package
java -jar target/campus-wall-0.0.1-SNAPSHOT.jar --spring.profiles.active=dev
```

存盘后运行:
```bash
cd campus-wall/campus_wall
chmod +x run-backend.sh     # 给脚本执行权限(只需一次)
./run-backend.sh            # 以后每次启动后端都跑这一句
```

**怎么算成功**:控制台最后出现 `Started CampusWallBackendApplication ... in X seconds`,且中途有 Flyway 的 `Successfully applied` 或 `Schema ... is up to date`。后端就在 `:8080` 起来了,**这个终端窗口别关**(关了后端就停)。

> ⚠️ Flyway 建表只需**第一台**连这个库的后端跑一次,后面其它 B 机连同一个库时会显示"up to date",正常。
> ⚠️ `APP_BASE_URL` 必须填 B 机自己的 IP,**不能 localhost**,否则前端拿到的图片/文件链接指向手机自己而打不开(原理见上面速查表)。
> (可选)内容审核 AI 复审默认连 Ollama;要用就加 `export AI_LOCAL_BASE_URL=http://$A:11434/v1`,且 A 机 Ollama 已放开 0.0.0.0 + 防火墙 11434。不设也不影响发帖(失败自动降级)。

### 第 4 步：连通自检(后端跑起来前先确认能连到 A 机)

在 **B 机**新开一个终端运行,确认网络通(任一项失败先解决再回到第 3 步):
```bash
nc -zv 172.21.160.212 3306 6379 9000 8001      # 四个端口都应显示 succeeded/open
curl http://172.21.160.212:8001/health          # 应返回 {"status":"ok","neo4j":true}
```
> 若 `nc` 不通:多半是 A 机防火墙没放行,让 A 机管理员执行本节开头「A 机一次性准备」的 ufw 那条命令。

### 第 5 步：跑前端(Node 18+)

```bash
cd campus-wall/campus-wall-frontend
npm install                 # 第一次较慢，装依赖

# 新建前端 .env 文件(项目里没有，要你建)。把 <本机IP> 换成后端所在 B 机的 IP：
printf 'VITE_API_BASE_URL=http://<本机IP>:8080\nVITE_WS_BASE_URL=ws://<本机IP>:8080\n' > .env

npm run dev:mp-weixin        # 产物输出到 dist/dev/mp-weixin
# 或最快验证：npm run dev:h5  →  浏览器打开终端给出的本地址
```
> 前端 `.env` 里填的是**后端所在那台 B 机**的 IP:两台 B 机各跑自己的全栈就各填各自;若是"221 跑后端、223 跑前端"这种拆分,则 223 的 `.env` 填 `172.21.160.221`。

**打开小程序**:`dev:mp-weixin` 只是编译,真正预览要用**微信开发者工具**(只有 Windows/Mac 版):
1. 打开微信开发者工具 → 导入项目 → 目录选 `campus-wall-frontend/dist/dev/mp-weixin` → AppID 填测试号。
2. 「详情 → 本地设置」勾选 **"不校验合法域名"**(否则连不上 http 内网后端)。
3. 若你的 B 机是 **Linux**(装不了微信开发者工具):用 `npm run dev:h5` 在浏览器里验证,或把 `dist/dev/mp-weixin` 拷到有微信开发者工具的电脑打开。

### 第 6 步：在小程序/H5 里验收

后端(第 3 步)+ 前端(第 5 步)两个终端都开着,微信开发者工具/浏览器打开后,照「[六、端到端验收清单](#六端到端验收清单)」逐条点一遍:主页 5 个板块、发二手帖、推广/组队卡片、AI 问答召回。能走通即部署成功。

> 本闭环已在 GB10 实测:真实发帖(二手/价格/联系方式) → 异步入库 Neo4j(intent 自动判 second_hand,向量1024) → AI 提问"求购二手山地自行车" → 召回该帖卡片(score≈0.89,带价格/联系方式/"是这个吗?")。

### 常见报错快查(B 机)

| 现象 | 原因 / 处理 |
|------|------------|
| `./run-backend.sh: Permission denied` | 忘了 `chmod +x run-backend.sh` |
| 启动报 `Communications link failure` / `Connection refused` | 连不到 A 机:先跑第 4 步 `nc -zv`;不通让 A 机放行防火墙 |
| 启动报 `Access denied for user 'root'` | `run-backend.sh` 里 `MYSQL_PASSWORD` 填错,对照 A 机 `ops/.env` |
| `Public Key Retrieval is not allowed` | MYSQL_URL 少了 `allowPublicKeyRetrieval=true`(脚本里已带,别删) |
| 小程序里图片/头像裂开打不开 | `APP_BASE_URL` 填成了 localhost,改成 B 机自己 IP 重启后端 |
| 小程序请求全部失败/域名校验 | 微信开发者工具勾"不校验合法域名";确认前端 `.env` 的 IP 是后端那台 |
| `mvnw: Permission denied` | `chmod +x mvnw` 后重试 |
