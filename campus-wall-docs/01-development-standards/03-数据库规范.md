# 数据库规范

本文档规定校园墙项目的数据库设计规范。

## 命名规范

### 表名

- 使用小写字母，下划线分隔
- 使用名词复数形式
- 避免使用 MySQL 关键字

```
# 正确
post                    # 帖子表
comment                 # 评论表
user_follow             # 用户关注关系表
chat_record             # 聊天记录表
moderation_log          # 审核日志表
admin_user              # 管理员账号表（独立 RBAC 体系）
admin_role              # 管理员角色表
admin_permission        # 权限码表
admin_user_role         # 管理员-角色关联表
admin_role_permission   # 角色-权限关联表
admin_oper_log          # 管理端操作审计日志表

# 错误
Post                    # 大写
postTable               # 驼峰
user-follow             # 中划线
order                   # 关键字
```

### 字段名

- 使用小写字母，下划线分隔
- 表意清晰，避免缩写（除非通用缩写）

```
# 正确
create_time
update_time
is_deleted
phone_number

# 错误
createTime
updt_time
ph_num
del_flag
```

### 索引名

```
# 主键
pk_表名

# 唯一索引
uk_表名_字段名

# 普通索引
idx_表名_字段名

# 组合索引
idx_表名_字段1_字段2
```

## 字段设计规范

### 通用字段（每个表必须包含）

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `id` | BIGINT | 主键，自增 |
| `create_time` | DATETIME | 创建时间，默认 CURRENT_TIMESTAMP |
| `update_time` | DATETIME | 更新时间，默认 CURRENT_TIMESTAMP ON UPDATE |
| `is_deleted` | TINYINT | 逻辑删除标志，0-未删除，1-已删除，默认 0 |

### post 表板块与交易扩展字段（V3.2/V3.3）

板块分类系统落地后，`post` 表新增以下业务字段（随 `V3.2`/`V3.3` 迁移加入）：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `is_top` | TINYINT | 是否置顶：0-否，1-是 |
| `price` | DECIMAL(10,2) | 二手价格，NULL 表示面议 |
| `salary` | VARCHAR | 兼职薪资 |
| `info_fee` | VARCHAR | 兼职信息费 |
| `contact` | VARCHAR | 联系方式（前端可一键复制）|
| `banner_object_name` | VARCHAR | 推广 Banner 大图的 MinIO 对象名 |
| `is_sold` | TINYINT | 二手是否已售出：1-已售（卡片置灰）|

### 常用字段类型

| 场景 | 推荐类型 | 说明 |
|------|----------|------|
| 主键 | BIGINT | 自增，足够大 |
| 状态/类型 | TINYINT | 0-255 足够 |
| 布尔值 | TINYINT(1) | 0=false, 1=true |
| 短文本 | VARCHAR(255) | 标题、昵称等 |
| 长文本 | TEXT | 内容、描述等 |
| 超长文本 | LONGTEXT | 大段内容 |
| 时间 | DATETIME | 带时区信息 |
| 金额 | DECIMAL(10,2) | 精确计算 |
| JSON | JSON | MySQL 5.7+ |

### 字段注释

每个字段必须添加注释说明：

```sql
CREATE TABLE post (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    user_id BIGINT NOT NULL COMMENT '发布用户ID',
    category_id INT NOT NULL COMMENT '分类ID',
    title VARCHAR(255) COMMENT '帖子标题',
    content TEXT NOT NULL COMMENT '帖子内容',
    images JSON COMMENT '图片URL数组',
    view_count INT DEFAULT 0 COMMENT '浏览次数',
    like_count INT DEFAULT 0 COMMENT '点赞次数',
    status TINYINT DEFAULT 0 COMMENT '状态：0-正常，1-待审核，2-已拒绝',
    is_top TINYINT DEFAULT 0 COMMENT '是否置顶：0-否，1-是',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    is_deleted TINYINT DEFAULT 0 COMMENT '是否删除：0-否，1-是',
    INDEX idx_user_id (user_id),
    INDEX idx_category_id (category_id),
    INDEX idx_status_create_time (status, create_time)
) COMMENT='帖子表';
```

## 索引设计规范

### 索引原则

1. **WHERE 条件字段**：查询条件中的字段必须建立索引
2. **ORDER BY 字段**：排序字段需要索引
3. **JOIN 字段**：关联字段需要索引
4. **覆盖索引**：尽量使用覆盖索引减少回表
5. **联合索引**：遵循最左前缀原则

### 索引示例

```sql
-- 单列索引
CREATE INDEX idx_user_id ON post(user_id);

-- 联合索引（最左前缀）
CREATE INDEX idx_status_create_time ON post(status, create_time);
-- 支持：WHERE status = ? AND create_time > ?
-- 支持：WHERE status = ?
-- 不支持：WHERE create_time > ?（缺少最左列）

-- 唯一索引
CREATE UNIQUE INDEX uk_phone ON user(phone);
```

### 索引注意事项

- 单表索引数量不超过 5 个
- 索引字段区分度要高（如性别字段不适合建索引）
- 频繁更新的字段谨慎建索引
- 过长字段使用前缀索引：`INDEX idx_title (title(20))`

### 版本号规则

- 主版本号：重大结构变更（如新增模块）
- 次版本号：增量变更（如新增表、字段）
- 版本号只能递增，不能回退

### 迁移脚本规范

```sql
-- V3.x__add_moderation.sql 示例
-- 添加内容审核相关表

-- ============================================
-- 审核配置表
-- ============================================
CREATE TABLE moderation_config (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    config_key VARCHAR(64) NOT NULL COMMENT '配置键',
    config_value VARCHAR(512) COMMENT '配置值',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE INDEX uk_config_key (config_key)
) COMMENT='审核配置表';

-- ============================================
-- 审核日志表
-- ============================================
CREATE TABLE moderation_log (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    target_type TINYINT NOT NULL COMMENT '目标类型：1-帖子，2-评论',
    target_id BIGINT NOT NULL COMMENT '目标ID',
    status TINYINT NOT NULL COMMENT '审核结果：0-通过，1-拒绝',
    reason VARCHAR(255) COMMENT '审核原因',
    operator_id BIGINT COMMENT '操作人ID',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_target (target_type, target_id),
    INDEX idx_create_time (create_time)
) COMMENT='审核日志表';
```

### 迁移原则

1. **脚本必须可幂等**：建表用 `CREATE TABLE IF NOT EXISTS`；但 **MySQL 8 不支持 `ADD COLUMN ... IF NOT EXISTS` / `CREATE INDEX ... IF NOT EXISTS`**（实测报 1064），加列/加索引需用 `information_schema` 查存在性 + `PREPARE`/`EXECUTE` 动态语句做幂等守卫（见下）。
2. **只增不改**：不修改已有表结构（如需修改，新增迁移脚本）
3. **数据迁移单独处理**：大批量数据迁移单独写脚本，避免阻塞
4. **测试后再提交**：本地验证通过后再提交到版本库

### MySQL 8 加列/加索引幂等守卫（必备写法）

```sql
-- 幂等加列：先查 information_schema 再决定是否 ALTER
SET @col_exists = (
    SELECT COUNT(*) FROM information_schema.COLUMNS
    WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'post' AND COLUMN_NAME = 'is_sold'
);
SET @ddl = IF(@col_exists = 0,
    'ALTER TABLE post ADD COLUMN is_sold TINYINT DEFAULT 0 COMMENT ''是否已售出''',
    'SELECT 1');
PREPARE stmt FROM @ddl; EXECUTE stmt; DEALLOCATE PREPARE stmt;

-- 幂等加索引：同理查 information_schema.STATISTICS
SET @idx_exists = (
    SELECT COUNT(*) FROM information_schema.STATISTICS
    WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'post' AND INDEX_NAME = 'idx_post_is_top'
);
SET @ddl = IF(@idx_exists = 0,
    'CREATE INDEX idx_post_is_top ON post(is_top)',
    'SELECT 1');
PREPARE stmt FROM @ddl; EXECUTE stmt; DEALLOCATE PREPARE stmt;
```

## 分库分表策略

当前阶段无需分库分表。当单表数据量超过 500 万时，考虑：

1. **归档策略**：将旧数据迁移到历史表
2. **分表策略**：按时间或用户 ID 分表
3. **读写分离**：主库写，从库读

## SQL 编写规范

### 查询规范

```sql
-- 正确：指定字段，避免 SELECT *
SELECT id, title, content, create_time
FROM post
WHERE status = 0
  AND is_deleted = 0
  AND create_time > '2024-01-01'
ORDER BY create_time DESC
LIMIT 10 OFFSET 0;

-- 错误
SELECT * FROM post WHERE status=0;
```

### 批量操作

```sql
-- 批量插入（推荐）
INSERT INTO post (user_id, title, content)
VALUES (1, '标题1', '内容1'),
       (2, '标题2', '内容2'),
       (3, '标题3', '内容3');

-- 批量更新（MyBatis-Plus saveOrUpdateBatch）
```

### 避免慢查询

- 不使用 `SELECT *`
- 大表分页使用游标或延迟关联
- 避免在索引字段上使用函数
- `LIKE` 查询避免前缀通配符 `%abc`

## 安全规范

1. **敏感字段加密存储**：密码、身份证号等
2. **最小权限原则**：应用账号只授予必要权限
3. **禁止生产环境直接修改数据**：必须通过迁移脚本或管理后台
4. **SQL 注入防护**：使用 MyBatis-Plus，禁止字符串拼接 SQL
